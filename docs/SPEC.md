# AutoFolder(오토폴더) 기획서

> 프로그램 이름: **AutoFolder**(사용자 결정, 0.1.19부터). 화면에는 "AutoFolder · 새 파일 자동 정리".

> 원본(편집용): https://claude.ai/code/artifact/3e797a23-ced0-467f-9b4c-7d85e72913ae
> 화면 시안(눌러 볼 수 있음): https://claude.ai/artifact/47zLo1gXgvr5PqTTeFH6g6 — 같은 내용이 `docs/design/*.dc.html`에 있다.
> 이 파일과 원본이 다르면 원본이 우선이다. 바뀐 결정은 이 파일에도 반영한다.

## 1. 개요

바탕화면·다운로드에 새 파일이 저장되면 작은 창을 띄워, 클릭 한두 번으로 원하는 폴더에 넣게 해 주는 Windows 프로그램.
쓰는 사람마다 폴더 구조와 파일 이름 습관이 다르므로, 미리 정한 규칙 대신 **각자 만든 폴더와 쓰면서 쌓이는 규칙**으로 정리한다.

- 쓰는 사람: 만든 사람 본인 + 나눠 받을 선생님들. 컴퓨터에 익숙하지 않은 사람도 설명 없이 쓸 수 있어야 한다.
- 플랫폼: Windows 10·11. 설치형, 트레이 상주, 컴퓨터 켜면 자동 실행.

설계 원칙
1. 규칙이 없어도 바로 쓸 수 있다 — 폴더만 있으면 팝업에서 폴더를 눌러 넣는다.
2. 규칙은 쓰면서 생긴다 — 위치를 고르면 "다음에도 여기에?"라고 묻고, 파일 이름의 단어를 눌러 규칙으로 저장한다.
3. 폴더는 실제 폴더처럼 보인다 — 목록이 아니라 탐색기처럼 폴더 아이콘이 놓여 있고, 누르면 안으로 들어간다.
4. 실수해도 바로 돌린다 — 모든 이동은 되돌리기 가능, 기록이 남는다. 지우기는 휴지통으로만(되돌리기·복원 가능).
5. 깔끔하고 모던한 화면 — **칸 제목 띠**(`src/components/Band.tsx`, 사용자 요청: 일체감)는 어디서나 같은 모양과 색의 뜻: 파란 띠 = 지금 할 일·넣을 곳(넣을 파일, 추천 위치, 추천 위치가 있는 파일), 회색 띠 = 고르거나 참고하는 곳(이미 있는 파일, 폴더, 최근 넣은 곳, 직접 골라야 하는 파일 — 아래 칸도 회색 바탕). 쓰는 곳: 자동 분류 카드, 새 파일 창(추천 위치·최근 넣은 곳·폴더에서 고르기, 아래 "넣을 곳"은 연한 파란 줄), 정리함 파일 칸(추천 위치가 있는 파일 / 직접 골라야 하는 파일로 나눔), 폴더 칸("폴더 n", "이 폴더의 파일 n"), 최근 정리(날짜별 "오늘 n · 어제 n · 그 전 n", 내리는 동안 위에 붙음. 줄 아래 때는 오늘이면 "3분 전", 어제면 "오후 3:20"), 정리 규칙("내 규칙 n", "단어 묶음 n"), 파일 검색("찾은 파일 n" + 찾은 범위 + 거르기), 설정(칸 제목), 새 파일 창에서 넣은 뒤 묻는 카드(파란 띠 "다음에도 여기에 넣을까요?", "규칙을 바꿀까요?"). 처음 설정과 이름 바꾸기 화면은 띠 없이. 시험판 표시("시험판 · PR n")는 왼쪽 위 이름 아래 노란 줄. 한글은 단어 중간에서 줄바꿈하지 않고(`word-break: keep-all`), 버튼 줄에서 버튼 하나만 다음 줄로 내려가지 않는다. 어색한 줄바꿈도 막는다(사용자 요청): 가운뎃점으로 이은 말("학년도·학기(3월·9월)")은 점 앞뒤에서 끊지 않고, 빈칸이 든 짧은 ‘…’ 말은 가운데서 끊지 않으며(`src/lib/keepDots.ts`가 화면 전체에 적용), 마지막 줄에 낱말 하나만 남지 않게 줄을 고르게 나눈다(`text-wrap: pretty`). 처음 설정 카드는 설명이 한 줄에 들어가게 넉넉하게(760px). 형식 배지(HWPX·XLSX 같은 네 글자)도 칸 크기에 맞춰 글씨를 줄여 한 줄로.

## 2. 핵심 흐름

```
새 파일 저장(바탕화면·다운로드)
  → 저장 끝났나 확인(약 2초간 변화 없음)
  → [자동 분류 모드] → 이름·형식으로 나눌 수 있으면 이동 + 알림, 모르면 정리함으로(4-1)
  → [모아 두고 나중에 정리] → 팝업 없이 정리함으로
  → [바로 정리 모드 + 규칙에 맞음] → 팝업 없이 이동 + 알림(팝업 창에 "규칙대로 정리했어요" + 되돌리기, 8초 뒤 닫힘)
  → [그 외] → 팝업
        ├ 넣기 → 폴더로 이동·기록 → 규칙 만들기 카드("다음에도 여기에?")
        └ 나중에 정리 → 정리함 → (끌어다 놓기·골라서 넣기·숫자 키) → 폴더로 이동·기록
```
기본 설정은 "바로 물어보기 + 추천만"이라 대부분의 파일이 팝업을 거친다.
새 파일 알림 방식(처음 실행에서 고르고 설정에서 바꿈)
- **바로 물어보기**(기본): 새 파일마다 팝업.
- **모아 두고 나중에 정리**: 팝업을 띄우지 않고 정리함에 모은다. 사용자가 원할 때 프로그램을 열어 정리한다.

## 3. 화면

### 3-1. 새 파일 팝업 (`docs/design/popup.dc.html`)
화면 오른쪽 아래, 폭 460px, 항상 위.
1. 파일 정보: 형식 배지(HWP·PDF…), 이름, "다운로드에 방금 저장됨 · 크기"(지켜볼 폴더 밖이면 "문서 › 카카오톡 받은 파일에 방금 저장됨"). 연필 버튼 = 이름 바꾸기. ⋯ 버튼 = 메뉴 [이 폴더는 묻지 않기](그 폴더·하위 폴더에 새 파일이 생겨도 묻지 않음, 이 파일과 그 폴더에서 기다리던 파일도 그 자리에 둠 — 설정 "묻지 않는 폴더"에 더해짐) · [저장된 위치 열기].
2. 추천 위치: 규칙에 맞는 폴더 하나 + 규칙 이름("이름의 ‘수행평가’ 규칙"). 누르면 선택.
3. 최근 넣은 곳 3개: 버튼 또는 숫자 키 1·2·3.
4. 폴더 창: 탐색기처럼 폴더 아이콘 격자(한 줄 4개). ‹ 버튼 + 경로(정리 폴더 › 평가 › 수행평가). 한 번 누르면 선택, 두 번 누르거나 › 를 누르면 안으로. 돋보기 = 폴더 이름 검색. 마지막 칸 "+ 새 폴더" = 지금 보는 폴더 안에 생성 후 선택.
5. 아래: "넣을 곳: 경로", [나중에 정리] [다른 위치…] [넣기]. Enter = 넣기, Esc = 나중에 정리.
6. 넣은 뒤: "정리했어요" + 되돌리기, 규칙 만들기 카드(파란 띠 "다음에도 여기에 넣을까요?" — 이름 단어 고르기, 넣은 폴더 이름과 같은 단어는 미리 골라 둠). "이번만" = 닫기. 추천대로 넣었으면 카드 대신 "…규칙대로 넣었어요".
- 추천이 있으면 그 폴더를 골라 둔 채, 그 폴더의 상위 폴더가 열린 채 시작(폴더 칸에 "추천" 표시). 추천 폴더가 아직 없으면(새 연도·학기) 넣을 때 만든다.
- 여러 파일이 한꺼번에 오면 하나씩 + "남은 파일 n개 · 모두 추천대로".
- **한꺼번에 생긴 파일**(사용자 요청, 내 PC 어디든과 함께): 감시가 한 번에 찾은 새 파일 중 물어볼 파일이 6개 이상이면(압축 풀기·폴더째 복사) 하나씩 묻지 않고 정리함에 모은 뒤 팝업에 한 번만 알린다 — "새 파일 n개가 한꺼번에 생겼어요", 앞의 3개(이름·위치), "그 밖에 n개", [정리하지 않기](정리함에서 뺌, 파일은 그 자리에) [정리함에서 정리](메인 창 정리함). ✕·Esc = 닫기만(정리함에 둠). 지켜볼 폴더 밖에서 한 번에 300개 넘게 생기면 프로그램 설치·큰 폴더 복사로 보고 정리함에도 넣지 않는다.

### 3-2. 정리함 (`docs/design/inbox.dc.html`)
메인 창. 미룬 파일, 추천 없는 파일, 팝업을 그냥 닫은 파일이 모인다.
- 왼쪽 파일 칸: 맨 위 **[정리할 파일 n | 최근 정리]** 두 칸, 그 아래 폴더 탭(전체·다운로드·바탕화면… — 지켜볼 폴더는 그 하위 폴더까지 한 탭, 그 밖에서 찾은 파일은 문서·사진·동영상·음악 탭, 어디에도 안 들면 "다른 곳"), 배지·이름·출처와 시각, 추천 위치 + [넣기], [모두 고르기] 줄 오른쪽에 [자동 분류](시안의 [추천대로 모두]를 대신함: 미리보기 창에서 넣을 폴더별로 보여 주고, 옮기거나 빼고, 확인하면 한꺼번에 넣음 — 4-1). 미리보기 창은 프로그램 창을 거의 다 채운다(창을 키우면 같이 커짐, 사용자 요청), 위 버튼으로 보는 방식을 고른다(고른 것을 기억함, 사용자 요청):
    - **카드로 보기**(기본): 넣을 폴더마다 네모 카드(포스트잇을 줄 맞춰 붙인 것처럼) 안에 그 폴더로 갈 파일. **모든 카드는 같은 크기**(360px, 줄 맞춰 깔끔하게, 사용자 요청. 폴더가 많으면 줄이 늘고 판 안에서 내려 봄)이고 넣을 파일이 많으면 카드 안에서 내려 본다. 파란 띠 "넣을 파일 n" 아래에 넣을 파일, 회색 띠 "이미 있는 파일 n" 아래에 **그 폴더에 이미 있는 파일**(회색 바탕, 칸마다 따로 내려 봄. 넣을 파일 칸은 이미 있는 파일이 있을 때 딱 3줄 높이까지 — 반 줄이 걸치지 않게)을 보여 줘서 무엇이 들어 있는 폴더인지 보고 나눌 수 있다(사용자 요청). 이미 있는 파일은 끌거나 고를 수 없다(보기만). 판 전체가 내려가고, 끄는 동안 판 끝에 대면 저절로 내려간다. 카드 이름은 마지막 폴더(연도·학기·학급 폴더면 뜻 있는 위 폴더까지 "수행평가 › 2026 › 2학기"). **"정리함에 남기기"는 왼쪽에 창 높이만큼 길게**(그 안에서 내려 봄, 사용자 요청) 두고, 남은 오른쪽 공간에 폴더 카드를 놓는다. 오른쪽만 내려 보며 왼쪽은 그대로라, 왼쪽에서 파일을 집어 오른쪽 폴더에 놓기 쉽다. 폴더 카드 끝에 [+ 폴더 추가](목록에 없는 폴더를 골라 빈 카드를 만듦). 끄는 동안 카드 자리는 바뀌지 않는다. 정리 폴더 안의 폴더는 추천된 파일이 없어도 **늘 카드로 보인다**(오른쪽 순서: 추천된 폴더 → 나머지 폴더 → 폴더 추가). 안쪽 폴더는 [+ 폴더 추가]로.
    - **목록으로 보기**: 왼쪽은 폴더별 묶음 목록(따로 내려감), 오른쪽은 정리함과 같은 폴더 격자(제자리, 누르면 안으로).
    - **체크 상자 없이 '누르기' 하나로**(사용자 결정): 파일을 누르면 골라지고(파란색), 다시 누르면 풀린다. 고른 파일 하나를 끌면 **고른 파일이 다 같이** 옮겨진다(끄는 동안 "자료_03.pdf 외 2"). 카드마다 띠 오른쪽 [모두 고르기]/[고르기 풀기]. **Shift를 누른 채 누르면** Windows 탐색기처럼 마지막으로 누른 파일부터 거기까지(같은 카드 안) 모두 고른다(사용자 요청). **분류에서 빼기**(사용자 요청: 끌지 않고 빼게): 고른 파일이 있는 폴더 카드의 띠에 [n개 빼기], 창 아래 왼쪽에 "n개 고름 · [분류에서 빼기] [고르기 풀기]" — 고른 파일을 왼쪽 칸(정리함에 남기기, 다시 정리하기는 그대로 두기)으로 옮긴다. **폴더 카드에 있는 파일은 모두 나누고**, 왼쪽 칸의 파일만 옮기지 않는다([n개 나누기]의 n). 왼쪽 칸으로 뺀 파일에는 "PDF에서 뺌"처럼 원래 폴더가 보이고 ↺로 되돌린다. 예전의 체크 끄기·[모두 해제]·[전체 체크 해제]는 없앴다(체크를 꺼도 그 카드에 남아 하나씩 옮겨야 했음 — 사용자 보고).
    - 두 보기 모두 **파일을 끌어 다른 폴더(카드·묶음·폴더 격자·정리함에 남기기)에 놓으면 그 파일만 넣을 곳이 바뀐다**("직접 옮김", ↺ 원래대로, [옮긴 것 모두 되돌리기]). 직접 옮긴 파일은 규칙·자동 분류 기록 없이 일반 넣기로 넣는다(사용자 요청).
- 오른쪽 폴더 칸: 경로 + 폴더 아이콘 격자(누르면 안으로), 위에 숫자 키가 붙은 "자주 쓰는 폴더".
- **폴더 안 파일**(사용자 요청): 폴더 격자 아래에 지금 폴더 바로 안의 파일(배지·이름·고친 날짜·크기, 최근순/이름순 — 고른 정렬은 이 PC에 기억). 지금 연 폴더 하나만 디스크에서 읽고(폴더 칸의 "파일 n개"를 셀 때도 같은 목록을 읽으므로 더 무겁지 않음), 미리보기 그림은 만들지 않는다. 300개까지 그리고 나머지는 탐색기에서 보도록 안내. 정리 폴더와 그 안쪽만 읽는다. 여러 개 골라 한꺼번에 끌 수 있고(위 고르기), 고르면 제목 줄에 "n개 고름 · [고르기 풀기]", 하나만 골랐을 때 [위치] [열기].
  - **폴더는 위에 고정**(사용자 요청: 파일을 고른 채 내려도 옮길 폴더가 보이게): 경로·자주 쓰는 폴더·폴더 격자는 그대로 있고 아래 파일 목록만 따로 내려간다. 폴더가 아주 많으면 폴더 격자도 따로 내려가고(파일 목록은 최소 130px), 파일이 없는 폴더는 남는 자리를 폴더 격자에 준다. 창 높이가 680px 이하로 아주 낮으면 예전처럼 칸 전체가 내려간다.
  - **들여다보기만**: 한 번 누르면 고르기([위치] [열기]), 두 번 누르면 열기, 끌어서 다른 폴더(격자·자주 쓰는 폴더)에 놓으면 옮기기(이동 기록·알림의 되돌리기). 같은 폴더에 놓으면 그대로("이미 이 폴더에 있어요"). 지우기·복사·이름 바꾸기는 넣지 않고 [탐색기에서 열기]로 넘긴다(탐색기 역할을 다 따라 만들지 않음 — 헷갈리고, 지키는 약속이 늘어나므로).
- **정리 기록**(사용자 요청: 노션 등에 이동 기록을 남기는 것처럼, 앱 안에서): 왼쪽 메뉴 '정리함' 아래 "정리 기록" 화면. 넣기·옮기기·이름 한꺼번에 바꾸기·휴지통 기록을 모두(새것부터 3,000개, 화면에는 200개씩 [더 보기]) — 날짜 띠(오늘·어제·10월 14일 (화)) 아래 줄마다 시각 · 파일 · 원래 있던 곳 → 넣은 곳(정리 폴더 안은 "업무 › 공문", 밖은 "다운로드"·"바탕화면 › 생기부", 휴지통은 "→ 휴지통", 이름 바꾸기는 "이름 바꿈 옛 이름 → 새 이름") · 상태와 버튼(지금 그 자리에 있으면 [위치] [되돌리기], 휴지통에 있으면 [되살리기], 되돌린 것 "되돌림", 그 뒤에 또 옮겨진 것 "다시 옮김", 되살린 것 "되살림"). 파일 이름·폴더로 찾기, 기간(전체·오늘·이번 주·이번 달). [엑셀 파일로 저장] = 지금 보이는 기록(찾기·기간 적용)을 저장 창에서 고른 **서식 있는 .xlsx**로(사용자 요청: 처음의 CSV는 칸 너비·색·필터가 없었다; rust_xlsxwriter, MIT/Apache-2.0). 시트 "정리 기록", 파란 제목 줄(#2B59C3, 흰 굵은 글씨, 맨 위 고정 + 필터), 열: 날짜(진짜 날짜 yyyy-mm-dd) · 시각(hh:mm) · 종류 · 파일 이름(굵게) · 원래 있던 곳 · 넣은 곳(화면처럼 짧게) · 상태(되돌림·다시 옮김 회색, 휴지통에 있음 빨강) · 원래 경로 · 넣은 경로(전체, 회색), 칸 너비를 미리 맞추고 한 줄씩 옅은 회색 줄무늬, 맑은 고딕 10, 가로 인쇄·폭 맞춤. Rust는 .xlsx에만 쓴다. 기록은 이 PC의 data.db(moves·deletions)에만 있고 밖으로 보내지 않는다(네트워크 규칙). `src-tauri/src/movelog.rs`, `src/screens/LogPage.tsx`. 정리함의 최근 정리 탭 맨 아래 [전체 기록 보기]로 이 화면에 온다.
- **최근 정리 탭**(사용자 요청): 파일 칸 맨 위 두 칸 중 "최근 정리" = 최근에 넣거나 옮긴 파일(이동 기록에서 되돌리지 않은 것, 이름 한꺼번에 바꾸기 묶음 제외, 그 뒤에 또 옮겨져 그 자리에 없는 것 제외, 새것부터 100개). 줄마다 원래 있던 곳 → 넣은 폴더(정리 폴더 이름은 빼고 "업무 › 공문"), 시각, [위치] [되돌리기]. 줄을 누르면 오른쪽 폴더 칸이 그 폴더를 열고 그 파일을 골라 둔다. 두 번 누르면 파일 열기.
  - 되돌리기: 지켜볼 폴더(다운로드·바탕화면 등)에서 넣은 파일은 원래 자리로 + 정리함으로, 그 밖(정리 폴더 안에서 폴더끼리 옮긴 것, 다른 폴더 정리하기로 옮긴 것)은 원래 폴더로만(정리함에 넣지 않음).
- 배치: 두 칸은 창 크기와 상관없이 항상 나란히(파일 칸 240~460px). 정리함 화면은 창 높이에 맞춰 고정되어 화면 전체는 내려가지 않고(두 칸이 어긋나지 않게), 목록·폴더는 칸 안에서 따로 내려간다. 폴더 탭은 늘 한 줄: 자리가 모자라면 들어가는 만큼만 보이고 나머지는 끝의 [더 보기 n ▾] 메뉴로(고른 탭은 늘 보임). 예전처럼 탭을 옆으로 밀어 숨기면 지켜볼 폴더가 3~4개일 때 "최근 정리"가 잘려 보였다(사용자 보고). 지켜볼 폴더 중 파일이 있는 곳이 하나뿐이면 폴더 탭 줄은 두지 않는다. 폴더 격자는 창이 넓으면 한 줄에 더 많이. 창이 좁으면(1000px 이하) 왼쪽 메뉴는 아이콘만. 파일이 없는 폴더 탭은 숨긴다.
- 폴더 격자는 늘 지금 디스크와 같게: 프로그램 어디서든(정리함·팝업·자동 분류·설정) 폴더를 만들거나 이름을 바꾸거나 옮기거나 휴지통으로 보내면 열려 있는 모든 폴더 격자가 바로 새로 읽는다. 탐색기에서 정리 폴더 안에 폴더를 만들거나 지워도 2초 안에 반영(파일 검색의 실시간 감시를 같이 씀). 창을 나갔다 들어올 필요 없음(사용자 요청).
  - 자주 쓰는 폴더(1~6): 지금은 자동 — 넣은 횟수가 많은 폴더부터, 모자라면 정리 폴더 바로 아래 폴더로 채움. 누르면 그 폴더로 이동, 파일을 끌어 위에 놓아도 됨. 직접 고르는 설정은 6단계(설정)에서.
- 폴더마다 ⋯ 메뉴: 이름 바꾸기 · 다른 폴더로 옮기기 · 휴지통으로 보내기(정리 폴더 안쪽만, 모두 되돌리기 가능). 이름을 바꾸거나 옮기면 그 안으로 옮긴 기록의 경로도 따라 바뀐다.
- 파일을 고르면 [휴지통] 버튼: 고른 파일을 휴지통으로(되돌리면 정리함으로 돌아옴).
- **기존 폴더 다시 정리하기**(사용자 요청): 이미 있는 폴더의 파일을 자동 분류 창(카드·끌어 옮기기·[모두 해제])으로 다시 나눈다. 왼쪽 칸은 "정리함에 남기기" 대신 **"그대로 두기"**(모르는 파일은 원래 자리). 창 위 "안쪽 폴더의 파일도"(기본 끔 — 켜면 원래 폴더 구조가 흩어지므로). 저장이 끝나지 않은 파일·바로 가기·숨긴 파일은 빼고, 2,000개까지만 읽는다. Windows·프로그램 폴더는 고를 수 없다. 옮긴 것은 기록되고 되돌리면 원래 폴더로(정리함에는 넣지 않음).
  - **다른 폴더 정리하기**: 정리함 제목 오른쪽 버튼 → 폴더 고르기 창. 정리 폴더 밖 폴더(예전 자료·USB)의 파일을 정리 폴더로. 넣을 곳은 자동 분류와 같다(규칙 → 이름 → 형식). 안쪽까지 읽어도 정리 폴더는 뺀다.
  - **이 폴더 다시 나누기**: 정리 폴더 안 폴더의 ⋯ 메뉴. 이름으로 정해지는 파일만 옮기고 형식만으로는 옮기지 않는다('개인'의 PDF가 '형식별'로 빠지지 않게). 지금 있는 폴더가 곧 넣을 곳이면 그대로.
  - **원래 폴더 이름도 단서**(사용자 요청): 파일 이름으로 모르거나 형식으로만 정해진 파일은 원래 있던 폴더 이름(그 파일의 폴더 → 고른 폴더 순)으로 ②처럼 찾는다(예: '생기부' 폴더의 김민찬.pdf → 자동 분류 단어 '생기부' → 생활기록부). 까닭은 "원래 폴더 ‘생기부’".
  - **새 폴더 제안**: 넣을 곳이 없거나 형식으로만 정해진 파일 중 이름에 같은 낱말(한글 2자·영어 3자 이상, 숫자·기호에서 끊음, '최종·사본·스캔' 같은 말 제외)이 든 파일이 3개 이상이면 그 낱말로 새 폴더 카드("새 폴더" 표시, 까닭 "이름의 ‘계약서’ 3개 · 새 폴더 제안"). 많은 낱말부터(같으면 긴 낱말), 한 파일은 한 폴더에만, 12개까지. 자리: 다시 나누는 폴더 안 / 다른 폴더면 정리 폴더 바로 아래(집·개인은 파일 종류가 같으면 그 종류 폴더 안, 예: 문서 › 계약서). [나누기]를 누를 때만 폴더를 만든다.
- 파일 목록 맨 아래(목록이 비면 가운데에 크게) [지금 있는 파일 가져오기]: 지켜볼 폴더에 원래 있던 파일(시작 전부터 있던 파일)을 정리함으로 불러온다. 이미 정리함에 있는 파일은 그대로.
- 넣는 방법: 폴더 아이콘 위로 끌어다 놓기 · 골라서 폴더 아래 "여기에 넣기"(폴더 안에서는 "이 폴더에 넣기") · 골라서 숫자 키.
  - 고르기는 자동 분류 창과 같다(사용자 요청: 정리함 왼쪽 목록과 이 폴더의 파일 모두). 체크 상자 없이 누르면 골라지고(파란색) 다시 누르면 풀리며, Shift를 누른 채 누르면 마지막으로 누른 파일부터 거기까지 모두 고른다. 고른 파일 하나를 끌면 고른 것이 다 같이 옮겨진다("… 외 2개"). 왼쪽 목록 위 줄: 고르기 전 [모두 고르기] [자동 분류], 고른 뒤 "n개 고름 · 숫자 키로도 넣어요"(좁아도 한 줄, 예전 "‘여기에 넣기’나 숫자 키로 넣어요"는 단어 중간에서 꺾였음 — 사용자 보고) [휴지통] [고르기 풀기].
  - 끌 때: 끌리는 파일 표시는 마우스 오른쪽 아래에 붙어 다니고, 놓을 곳은 **마우스 아래에 있는 폴더**다(자동 분류 창도 같음). 예전에는 긴 줄의 오른쪽을 잡고 끌면 표시가 마우스에서 떨어지고 표시가 겹친 다른 폴더에 들어갔다(사용자 보고). `src/lib/dnd.ts`.
- 끄는 동안 놓일 폴더 = 파란 아이콘 + 점선 테두리 + "놓으면 여기로".
- 넣을 때마다 "n개 파일을 … 에 넣었어요 · 되돌리기".
- 왼쪽 메뉴: 정리함(개수) · 정리 기록 · 파일 검색 · 이름 바꾸기(3-4) · 정리 규칙 · 설정, 아래 작동 상태.

### 3-3. 시안 없는 화면 (같은 스타일)
- 파일 검색: 메인 창 왼쪽 메뉴 "파일 검색" = 오른쪽 화면에서 찾는다(따로 창을 띄우지 않음 — 0.1.14의 별도 검색창은 사용자 요청으로 없앰). 단축키(기본 Alt+Space, 설정에서 Ctrl+Alt+F · Ctrl+Shift+Space · 쓰지 않기)·트레이 "파일 검색"은 메인 창을 앞으로 + 검색 화면 + 입력 칸에 초점. 입력 즉시 결과(어디서 찾는지 표시: PC 전체(Everything) / PC 전체(파일 n개) / 읽는 중 / 정리 폴더와 지켜볼 폴더), ↑↓ 고르기, Enter = 열기, Ctrl+Enter = 위치 열기(탐색기에서 골라 둠), Esc = 검색어 지우기, 고른 줄에 [위치] [열기]. 연도·학기·학급으로 거르기(지금 결과에 있는 값만). 결과는 탐색기의 "자세히" 보기처럼 표(사용자 요청): 열 = 이름 · 위치 · 수정한 날짜(2026-10-16 오후 8:53) · 유형(한글 문서·PDF 문서…) · 크기, 제목 줄은 내려도 위에 남음. 열 제목을 누르면 정렬, 누를 때마다 처음 방향(이름·유형 가나다순, 날짜 최근 것부터, 크기 큰 것부터) → 거꾸로 → 기본 순서(이름에 맞는 것 먼저), 화살표로 표시, [기본 순서로] 링크. 결과를 최대 200개로 자르기 **전에** 정렬(자체 색인은 Rust에서, Everything은 SDK의 Everything_SetSort), 이름은 탐색기처럼 숫자를 크기대로(파일2 < 파일10), 유형이 같으면 이름순. 고른 정렬은 이 PC에 기억. 고른 줄에만 [위치] [열기]. 열 너비(사용자 요청, 탐색기처럼): 열 제목 사이 선을 끌어 바꾸고, 두 번 누르면 그 열의 가장 긴 내용에 맞춤, 바꾼 너비는 이 PC에 기억. 너비를 바꾸기 전에는 창에 맞춰 나눠 쓰고, 창이 좁으면 위치·유형 칸을 숨기고 위치는 이름 아래에. 바꾼 뒤에는 그 너비 그대로, 넓으면 표 안에서 옆으로 내려 본다. 다른 화면에 갔다 와도 검색어는 남는다.

  - 정리 폴더 위치 바꾸기: 다른 폴더를 고르면 앞으로 거기에 정리한다. 원래 폴더·파일은 옮기지 않고, 직접 고른 자주 쓰는 폴더는 비운다. 예전 폴더로 가는 규칙은 그대로.

### 3-4. 이름 한꺼번에 바꾸기 (8단계, 사용자 요청)
폴더를 골라 그 안 파일 이름을 한꺼번에 바꾼다. 예: 학생 이름 파일 `고다윤.pdf` → `2026년 고다윤.pdf`, 번호로 된 과제 `05.hwp` → `김민지(5).hwp`, `scan_001.pdf` → `가정통신문 1.pdf`, `회의록_최종.hwp` → `회의록.hwp`, 사진 `IMG_2041.jpg` → `제주 여행 1.jpg`.
왼쪽 메뉴 "이름 바꾸기". 한 화면에서 위에서 아래로: ① 폴더와 파일 → ② 첫 파일을 원하는 이름으로 적기 → ③ 미리보기 → [n개 이름 바꾸기].

사용자 결정(0.1.15 뒤): 처음 만든 "틀 문법(`{원래 이름}` 등) + 규칙 알아내기"는 어려워서 쓰기 힘들었다 → **엑셀 빠른 채우기처럼 첫 파일만 원하는 이름으로 적으면 나머지가 따라오고(A), 알아들은 내용을 실제 값이 보이는 블록으로 보여 주고 고칠 수 있게(B)** 바꿨다. 학교 밖 사람도 쓸 수 있게 학교 낱말은 줄인다(명렬표 = 일반 사용자에게는 "번호·이름 목록").
미리 써 보기 페이지: https://claude.ai/artifact/XTWDhx3A9ExH64LHrQuthz

① 폴더와 파일
- [폴더 고르기]: 정리 폴더 밖 폴더도 된다. 단 드라이브 맨 위·Windows·Program Files·AppData 같은 시스템 폴더는 막는다.
- "하위 폴더 파일도"(기본 끔). 켜면 목록·미리보기에 하위 폴더 이름도 보인다.
- 파일 목록: 체크(기본 모두), 숨김·임시 파일(`~$`, `.tmp` 등, 5장 기준)은 뺀다. 순서: 이름순(2 < 10) / 고친 날짜순 / 직접(끌어서). 체크한 것 중 맨 위가 "첫 파일", 순서 번호도 이 순서. 최대 3,000개, 하위 폴더 8단계.

② 첫 파일을 원하는 이름으로 적기(확장자는 그대로)
- 적은 이름을 첫 파일과 견줘 **블록**으로 알아듣는다. 블록: [글자] [지금 이름(일부 지우기·바꾸기 포함)] [이름 조각 n] [올해] [오늘 날짜] [파일 날짜] [이름의 번호(앞의 0 그대로/빼기)] [순서 번호] [명렬표의 이름].
- 알아듣는 차례: ⑴ 지금 이름에서 일부만 지웠으면(또는 반 넘게 남기고 일부만 바꿨으면) "지금 이름에서 그 글자 지우기·바꾸기"(그 글자가 없는 파일은 그대로). 단, ⑵로 읽어도 되고 그쪽이 더 많은 파일을 바꾸면 ⑵ — 예: `면접자료_김태우_신소재공학` → `면접자료_김태우`는 학과가 파일마다 달라서 ‘_신소재공학’ 글자 지우기로는 첫 파일만 바뀌므로 [조각 1][_][조각 2]로 알아듣고 모든 파일의 학과 조각을 뺀다(사용자 요청). 같은 수면 글자 지우기(`_최종`처럼 같은 글자를 지운 경우) ⑵ 아니면 적은 이름 안에서 첫 파일의 값(명렬표 이름 → 지금 이름 → 이름의 번호 → 이름 조각 → 올해 → 오늘 → 파일 날짜, 긴 것부터, 대소문자 무시, 숫자 값은 앞뒤가 숫자가 아닐 때만)을 찾고 나머지는 글자 ⑶ 이름의 번호를 쓰지 않았으면 남은 숫자(연도 모양 2000~2099 빼고) 하나를 순서 번호로(시작 번호·자릿수는 적은 그대로).
- 이름의 번호: 숫자만 된 조각(연도·학급 `3-2`·학기 빼고)이나 `5번`, 없으면 글자에 붙은 숫자(`과제05`), 여럿이면 마지막. 학년반번호 다섯 자리(30205)는 끝 두 자리. 2000~2099는 연도로 보고 번호로 쓰지 않는다(사진 `IMG_2041`은 순서 번호로).
- 블록을 누르면 메뉴: 글자 고치기 · 순서 번호로/글자 그대로 · 올해 → 파일 날짜 · 앞의 0 그대로/빼기 · 앞으로/뒤로 · 빼기. [+ 넣기]로 블록 더하기. 블록을 고치면 첫 칸도 그 결과로 바뀐다(다시 알아듣지 않음). 첫 칸에 다시 적으면 다시 알아듣는다.
- 자주 쓰는 것(첫 칸을 채워 줌): 앞에 올해 붙이기 · 뒤에 오늘 날짜 붙이기 · 새 이름 + 번호 · 번호를 이름으로. 그리고 **[명렬표] 버튼은 늘 보인다**(누르면 붙여 넣는 칸, 읽은 사람 수 표시).
- 안내: 학생 이름처럼 보이는 글자(한글 2~4자) + 번호를 적었는데 명렬표가 없으면 "명렬표를 붙여 넣으세요" + 칸을 연다. [명렬표의 이름] 블록인데 명렬표가 없어도 같다.

명렬표(번호·이름 목록, 저장하지 않음)
- 나이스·엑셀에서 "번호 이름" 두 칸을 복사해 붙여 넣는다(탭·쉼표·공백 구분, 순서 상관없음, 머리글 줄은 건너뜀). 학년반번호 다섯 자리(30205)는 끝 두 자리를 번호로. 두 번 나온 번호는 알리고 뒤의 이름을 쓴다.
- 명렬표에 없는 번호는 빨갛게 표시하고 바꾸지 않는다.
- **디스크에 저장하지 않는다**(화면을 떠나거나 프로그램을 끄면 지운다). 학생 이름이 기록에 남는 것은 바꾼 파일 이름뿐.

③ 미리보기와 실행
- 표: 원래 이름 → 새 이름(첫 파일 줄 표시). 그대로(회색), 겹침(새 이름끼리 같거나 폴더에 이미 있음 → 덮어쓰지 않고 `(2)`를 붙인다고 표시), 건너뜀(빨강: 빈 이름, `\ / : * ? " < > |`, 경로 260자 넘음, 번호 없음, 명렬표에 없는 번호, 첫 파일과 조각 모양이 다름).
- [n개 이름 바꾸기]: 화면에 보이는 블록 그대로 다시 계산해 바꾼다. 서로 이름이 엇갈리는 경우(a→b, b→a)도 임시 이름을 거쳐 안전하게 — 먼저 모두 `~이름바꾸는중-….tmp`(감시·검색이 무시하는 이름)로 바꾼 뒤 새 이름으로, 그사이 자리가 찼으면 번호. 열려 있는 파일은 건너뛰고 끝에 알린다. 바뀐 이름은 새 파일 감시가 새 파일로 잡지 않는다.
- 바꾼 것은 모두 이동 기록(원래 경로 → 새 경로, 같은 묶음 번호 — DB 표 버전 6 `moves.batch`)에 남고, 알림 "n개 파일 이름을 바꿨어요 · **되돌리기**"로 묶음 전체를 한 번에 되돌린다(되돌릴 때도 임시 이름을 거침). 그 파일로 옮겼던 예전 이동 기록·정리함 항목은 새 이름을 따라간다. 규칙은 폴더 경로만 쓰므로 그대로.

## 4. 규칙

규칙 = "조건 → 저장 위치". 기본 생성 경로는 팝업에서 위치를 고른 뒤 단어를 눌러 저장. 정리 규칙 목록은 고치고 지우는 곳(확장자·출처 규칙은 여기서 "새 규칙"으로 만든다). 새 규칙은 맨 위에 놓인다(예전 규칙에 가려지지 않게).

조건(위에서부터 먼저 맞는 규칙 하나)
| 종류 | 예 | 비고 |
| --- | --- | --- |
| 파일 이름 단어 | ‘수행평가’ 포함, ‘2027’과 ‘수행평가’ 모두 포함, ‘중간고사’·‘기말고사’ 중 하나라도 포함 | 기본. 대소문자 무시. 단어가 여럿이면 규칙마다 "모두 들어 있으면 / 하나라도 있으면"(기본 모두) |
| 확장자 | .hwp, .hwpx | 단어와 함께 쓰면 둘 다 맞아야. 단어 없이 확장자만 있는 규칙은 단어 규칙이 하나도 안 맞을 때 마지막 기준 |
| 출처 | 다운로드에서 온 파일만 | 선택 |

저장 위치와 자동 하위 폴더
- 경로 일부를 **[연도] [학기] [학급]** 자리표시로 바꿀 수 있다. 팝업·규칙 편집의 "연도·학기 폴더는 파일마다 알아서 나누기"를 켜면, 고른 폴더 경로(정리 폴더 아래) 중 이름이 연도·학기·학급으로만 된 폴더가 자리표시가 된다: `2027` → [연도], `2027학년도` → [연도]학년도, `1학기/2학기` → [학기], `2027 1학기` → [연도] [학기], `3-2` → [학급]. `학급 3-2`처럼 다른 글자가 섞인 폴더는 그대로.
- 저장은 고른 폴더 경로 그대로 + "나누기" 여부. 폴더 이름을 바꾸거나 옮기면 규칙의 저장 위치도 따라 바뀐다. 자리표시 앞부분 폴더가 없어지면 그 규칙은 추천하지 않고 규칙 목록에 경고.
- 예: 평가 › 수행평가 › [연도] › [학기] → `2028_2학기_…` 파일은 … › 2028 › 2학기. 없으면 만든다.
- 값을 읽는 순서: 파일 이름 → 없으면 오늘 날짜.
- 학년도·학기: 3~8월 = 그 해 1학기, 9~12월 = 그 해 2학기, 1~2월 = 전년도 2학기. 경계 월은 설정에서 변경 가능.
- 연도: `2027`, `27학년도`. 학기: 1차 버전은 `n학기`만(`1-1` 같은 표기는 학급과 헷갈림).
- 학급: `3-2`, `3학년 2반`, `302` → `3-2`로 통일. 숫자 3자리(`302`)는 그 규칙이 [학급]을 쓸 때만. 학년 없이 `3반`이면 `3반` 폴더. 이름에 학급이 없으면 [학급] 폴더 단계는 건너뛴다(오늘 날짜로 정할 수 없으므로).
- 날짜와 섞인 `-`(`2027-10-13`)는 학급으로 보지 않는다. 연도는 2000~2099의 네 자리 숫자만(`20261013` 같은 여덟 자리는 아님). 오늘 날짜는 이 PC의 시간대 기준.

추천과 자동 이동
- 기본은 추천만. "바로 정리"를 켜면 규칙에 맞는 파일은 팝업 없이 이동 + 알림(되돌리면 팝업에서 다시 물어봄), 규칙 없는 파일은 "새 파일이 생기면" 설정대로(팝업). 옮기지 못하면(파일이 열려 있음 등) 팝업으로 물어본다.
- "모아 두고 나중에 정리"일 때는 바로 정리하지 않고 모두 정리함으로. 정리함에서 파일마다 추천 위치 + [넣기], 위에 [자동 분류].
- 같은 규칙에서 사용자가 추천과 다른 **같은** 폴더를 세 번 연속 고르면 넣은 뒤 "규칙을 바꿀까요?" → [그대로 두기] / [이 폴더로 바꾸기]. 중간에 추천대로 넣거나 다른 폴더를 고르면 처음부터 센다.
- 추천과 다른 곳에 넣었을 때(세 번째가 아니면)는 규칙 만들기 카드를 보여 준다.
- 기록: 추천(규칙)대로 넣은 이동은 그 규칙 번호를 남긴다(규칙 목록의 "n번 정리했어요", 되돌린 것 제외).

## 4-1. 자동 분류

규칙을 만들지 않아도 파일 이름·형식을 보고 알아서 나눈다. 사용자 결정(5단계): 정리함 버튼 + 새 파일 둘 다, 구별이 안 되는 파일은 정리함에 남김, 기준은 폴더 이름 + 교사용 단어 + 파일 형식.

- 순서: ① 정리 규칙 → ② 이름 단어 → ③ 파일 형식 → ④ 모르면 정리함(원래 자리 그대로).
- ② 이름 단어: 정리 폴더 안 폴더 이름(4단계 깊이까지, 두 글자 이상, 숫자만·연도·학기·학급 폴더 제외)과 "자동 분류 단어" 중 파일 이름에 든 **가장 긴 단어**(같으면 폴더 이름). 대소문자 무시.
- 자동 분류 단어(교사용 기본, 정리 규칙 화면에서 고침): 공문(공문·시행문·협조·회신), 회의록(회의록·협의회·회의), 계획서(계획서·계획), 가정통신문(가정통신문·통신문), 수업(수업·학습지·활동지·교안·지도안), 수행평가(수행평가·채점기준·루브릭), 지필고사(지필·중간고사·기말고사·문항정보표·이원목적·시험지·감독), 상담, 출결(출결·결석·지각·조퇴), 생활기록부(생활기록부·생기부·세특·세부능력·행동특성·창체·진로활동·동아리), 연수(연수·이수증). 폴더 자리는 교사용 예시 구조(예: 업무 › 공문).
  - 집·개인 기본 단어: **없음**(사용자 결정 — 쓰임새로 나눈 예시(업무·돈 관리·개인…)는 사람마다 맞지 않았다). 집·개인은 ③ 파일 형식으로 정리 폴더 바로 아래 종류 폴더에 넣는다: 문서(한글·워드·PDF·엑셀·발표 자료·텍스트) · 사진 · 동영상 · 음악 · 압축·설치(zip 등 + exe·msi). 사용자가 `문서 › 계약서`처럼 폴더를 만들면 ②의 폴더 이름으로 저절로 찾아 넣는다.
  - 같은 이름의 폴더가 정리 폴더 어딘가에 있으면(얕은 것부터) 거기로, 없으면 정해 둔 자리에 **만든다**.
- ③ 파일 형식: `정리 폴더\형식별\` 아래 한글 문서·워드 문서·PDF·엑셀·발표 자료·사진·동영상·소리·압축 파일·텍스트(없으면 만든다). 형식별 폴더 안의 폴더 이름은 ②의 기준이 아니다.
- ④ 설치 파일(.exe·.msi) 등 형식도 모르는 파일은 옮기지 않는다.
- 언제: 정리함 [자동 분류](미리보기 → 확인), 그리고 설정 "정리 방식 → 자동 분류"면 새 파일마다(묻지 않고 옮긴 뒤 팝업 창에 알림 + 되돌리기, 나누지 못한 파일은 "새 파일이 생기면" 설정과 상관없이 정리함으로).
- 팝업·정리함 줄의 "추천 위치"도 ①②로 정한다(③ 형식은 추천하지 않음). 추천대로 넣으면 규칙 만들기 카드는 띄우지 않는다.
- 파일 이름은 PC 안에서만 본다(AI 등 밖으로 보내지 않음).

## 5. 파일 감지 세부

- **새 파일을 찾는 곳**(설정 → 폴더, 사용자 요청: 인터넷·카카오톡·아이스톡 등 어떤 프로그램으로 받든, PC 어디에 저장하든 정리하고 싶다):
  - **내 PC 어디든**(기본. 예전 설정도 업데이트하면 이것 — 사용자 결정: 다시 설정하지 않아도 되게): 지켜볼 폴더 바로 아래 + 사용자 폴더(바탕화면·문서·다운로드·사진·동영상·음악, Known Folder API라 OneDrive로 옮긴 것도)와 Windows가 깔리지 않은 고정 디스크(D:\ 등)는 하위 폴더까지.
    - 사람이 받는 형식만: 문서(한글·워드·PDF·엑셀·발표·텍스트)·사진·동영상·소리·압축. 설치 파일(.exe·.msi)과 프로그램이 만드는 .db·.log 등은 보지 않는다.
    - 빼는 곳: 정리 폴더(이미 자리를 고른 파일), 묻지 않는 폴더, 파일 검색이 빼는 곳(AppData·`$Recycle.Bin`·`.`/`$`/`~`로 시작하는 폴더 등), 게임·앱 설치 폴더(Program Files·SteamLibrary 등).
    - 폴더 전체를 다시 읽지 않고 알림(`notify`, 하위 폴더까지)으로 온 파일만 본다. 만든 지 1시간이 넘은 파일은 옛 파일을 옮긴 것으로 보고 넘긴다. 이미 알린 파일을 탐색기로 옮기거나 이름만 바꾼 것(크기·만든 시각이 같음), 같은 자리에서 고쳐 저장한 것(만든 시각이 같음)도 다시 묻지 않는다. 10분 넘게 그대로인데 저장이 끝나지 않은 파일(빈 파일 등)은 그만 본다.
    - 지켜볼 폴더 밖에서 찾은 파일은 직접 저장한 문서일 수 있어 **'바로 정리'·'자동 분류'로 옮기지 않고 물어본다**('모아 두고 나중에 정리'면 정리함으로). 설정 화면에 이 안내를 보여 준다.
  - **고른 폴더만**(예전 방식): 지켜볼 폴더의 바로 아래 파일만(하위 폴더 X). 이걸 고르면 아래에 지켜볼 폴더 목록이 나온다.
  - **묻지 않는 폴더**: 여기(하위 폴더까지)에 새 파일이 생기면 묻지 않는다(지켜볼 폴더도 여기 들면 빠짐). 설정에서 [폴더 더하기]·[다시 묻기], 팝업 ⋯ "이 폴더는 묻지 않기". **기본으로 화면 캡처 폴더**(사용자 보고: 캡처를 찍을 때마다 창이 뜸): Windows 캡처 도구가 저장하는 사진\Screenshots와 녹화가 저장되는 동영상\Captures를 처음 한 번 더해 둔다(예전 설정도 업데이트하면 더해짐, `quietDefaultsAdded`). [다시 묻기]로 빼면 다시 넣지 않는다.
  - 메인 창 왼쪽 아래 상태 칸: "새 파일: 내 PC 어디든" / "지켜볼 폴더: 다운로드 · 바탕화면".
- 한꺼번에 찾은 파일은 한 묶음으로 넘긴다: 아직 쓰는 중인 파일(최근 4초 안에 바뀜)이 있으면 최대 10초 기다렸다 같이(3-1 "한꺼번에 생긴 파일").
- 방식: 파일 시스템 알림(`notify` 크레이트) + 1.5초 주기 확인 보조(저장 중인 파일이 있으면 0.5초).
- 저장 완료: 크기·수정 시각이 약 2초 그대로(3초 안에 팝업이 뜨도록) + 크기 > 0 + 같은 이름의 `.crdownload` `.part` `.download`가 없음.
- 건너뜀: `.crdownload .part .tmp .download .lnk .url .ini`, `~` `~$` `.`으로 시작, 확장자 없음(엑셀 임시), 숨김·시스템, 폴더.
- **백신 미끼 파일**(사용자 보고: 바탕화면에 `(gQfE6h.jpg` 같은 파일이 자꾸 생겨 창이 뜸): 안랩 V3가 랜섬웨어를 알아채려고 몰래 만드는 디코이 파일. 사진 형식(jpg·png·gif·bmp)이고 2MB 이하인 파일만 앞 64KB를 읽어 "decoy file"과 "AhnLab"이 둘 다 있으면(사진 정보 XMP에 "This is normal decoy file which is created by AhnLab…") 묻지 않고, 지금 있는 파일 가져오기·다른 폴더 정리하기·이름 바꾸기·폴더 안 파일 목록에서도 뺀다. 예전에 정리함에 들어간 것은 목록을 읽을 때 뺀다(파일은 그 자리에). 옮기거나 이름을 바꾸면 백신이 다시 만들거나 의심할 수 있어 건드리지 않는다.
- 시작 시 이미 있던 파일: 팝업 X. 정리함 "지금 있는 파일 가져오기"로.
- 열린 파일(잠김): "파일이 열려 있어요. 닫으면 옮길게요" 후 재시도(최대 3시간).
- 같은 이름: 덮어쓰지 않고 `이름 (2).hwp`.
- 다른 드라이브: 복사 → 원본 삭제, 삭제 실패 시 복사본 삭제 후 오류.
- 기록: (원래 위치, 옮긴 위치, 시각, 규칙). 되돌리기 시 감시가 다시 새 파일로 잡지 않게 표시.
- 일시 정지: 정지 중 들어온 파일은 팝업·자동 정리 없이 정리함으로. 프로그램을 다시 켜면 풀린다.
- **사용자 파일·폴더를 영구 삭제하는 코드는 만들지 않는다.** 지우기는 휴지통으로 보내기만(`trash` 크레이트), 보낸 기록(`deletions` 표)으로 되돌린다. 휴지통이 없는 드라이브(USB·네트워크)는 Windows가 바로 지울 수 있어 지우기를 막는다(고정 디스크만).

## 6. 검색

- 사용자 결정(7단계 뒤): Everything을 깔지 않아도 PC 전체에서 찾는다. Everything의 빠른 검색 엔진(NTFS 목록을 직접 읽음, 관리자 권한 필요)은 따로 설치하는 비공개 프로그램이고, SDK는 켜져 있는 Everything과 이야기하는 통로일 뿐이라 프로그램 안에 넣을 수 없다. 그래서 같은 일을 하는 **자체 색인**을 만든다.
- 순서: ① Everything이 켜져 있으면 Everything(공식 SDK, IPC, `Everything64.dll`, 역분석하지 않음) ② 아니면 자체 색인. 이미 Everything을 쓰는 PC는 그대로 빠르고, 없는 PC도 PC 전체를 찾는다. Everything 설치 파일은 함께 넣지 않는다(9단계에서 뺌).
- 자체 색인 범위(설정 "PC 전체에서 찾기", 기본 켬): 고정 디스크(C:\ D:\ …) 전체에서 빼는 곳 — 드라이브 바로 아래 Windows·Program Files·ProgramData·Recovery 등, 어디서든 AppData·node_modules·`$Recycle.Bin`·`.`/`$`/`~`로 시작하는 폴더, 숨김·시스템 속성, 바로 가기 폴더(심볼릭 링크·연결 지점). 파일은 `~$`·`.tmp`·`.crdownload`·`.lnk` 등을 뺀다. 끄면 정리 폴더(하위 폴더까지) + 지켜볼 폴더(바로 아래)만. 정리 폴더·지켜볼 폴더가 빼는 곳 안에 있어도 그것은 읽는다.
- 읽기: 켤 때 뒤에서(낮은 우선순위 스레드, 디스크도 양보). PC 전체를 처음 읽는 동안에는 정리 폴더·지켜볼 폴더부터 먼저 읽어 그 안에서 찾고, 화면에 "PC 전체를 읽는 중(파일 n개)"을 보여 준다. 다 읽으면 지금 검색어로 다시 찾는다.
- 최신으로 맞추기: 읽은 곳을 파일 시스템 알림(`notify`, 하위 폴더까지)으로 지켜보다가 바뀐 폴더만 2초마다 모아 다시 읽는다. 알림이 넘치거나(놓쳤을 수 있음) 2만 곳 넘게 한꺼번에 바뀌면 처음부터 다시 읽는다(10분에 한 번까지). PC 전체는 6시간마다, 정리 폴더 범위는 검색 화면을 열 때 2분이 지났으면 다시 읽는다. Everything이 켜져 있으면 메모리를 아끼려고 정리 폴더 범위만 읽어 둔다.
- 저장 방식: SQLite FTS5 대신 메모리 목록 + 글자 포함 검색(한글은 단어 중간도 찾아야 해서 — ‘평가’로 ‘수행평가’). 폴더는 한 번만, 파일은 폴더 번호 + 이름(한 덩어리 문자열에 이어 붙임)만 들고 있다. 최대 150만 개(약 100MB). 디스크에 저장하지 않는다(켤 때마다 새로 읽음).
- 찾는 법: 띄어 쓴 낱말이 모두 경로(폴더 이름 포함)에 있는 파일. 대소문자 무시(영문). 이름에 모두 있는 파일이 먼저, 그다음 최근에 고친 순. 최대 200개. Everything도 같은 식(파일만, 휴지통·임시 폴더 제외).
- 결과에 연도·학기·학급(파일 이름 → 없으면 가까운 폴더 이름)과, 규칙으로 넣은 파일이면 그 규칙을 붙여 거르기에 사용.
- `Everything64.dll`은 저장소에 넣지 않고, 설치 파일을 만들 때 `scripts/fetch-everything-sdk.ps1`이 voidtools 공식 배포본(Everything-SDK.zip)에서 받아 `src-tauri/resources/`에 넣는다(못 받으면 경고만 하고 자체 색인으로). 라이선스 고지는 `resources/THIRD_PARTY.txt` 하나(설치 폴더에 함께 들어가고, 설정 → 정보 → [오픈소스 라이선스]에서도 같은 글을 보여 줌): Everything SDK(MIT), Pretendard(SIL OFL 1.1 전문), Tauri·React·Zustand·dnd kit·rusqlite·trash·chrono·serde·windows-sys(MIT), Lucide·libloading(ISC), SQLite(공개 도메인), notify(CC0).

## 7. 설치·자동 실행·업데이트·배포

- 설치: Tauri NSIS, `installMode: currentUser`(관리자 권한 불필요, 이후 업데이트도).
- 자동 실행: autostart 플러그인(기본 켬, 처음 설정을 마칠 때 등록하고 켤 때마다 설정과 맞춤 — 예전 버전에서 업데이트해도 켜짐), `--autostart` 인자로 켜지면 창 없이 트레이로만. 개발용(디버그) 실행 파일은 등록하지 않는다. single-instance 플러그인: 이미 켜져 있으면 그 창을 앞으로.
- 업데이트: updater 플러그인. 시작 시 + 4시간마다 확인(예전: 하루 한 번). 설치 창은 띄우지 않는다(`installMode: quiet`, currentUser 설치라 UAC 없음).
  - **자동 업데이트**(설정 → 프로그램 "새 버전은 자동으로 설치", 기본 켬 — 사용자 요청: 누르지 않아도 버전이 다르면 업데이트되게. 예전 설정도 켬): 새 버전을 뒤에서 받아 두고(`download`), 프로그램을 쓰지 않을 때만 설치한다 — 메인 창과 새 파일 창이 닫혀 있고, 물어볼 파일·"바로 정리" 알림·한꺼번에 알림이 없을 때(`update_idle`, 1분마다 확인). 컴퓨터를 켜서 자동 실행된 직후가 가장 흔하다. 설치 뒤에는 트레이로 조용히 다시 켜지고(relaunch 표시 둘째 줄 `quiet`), 다음에 창을 열면 "0.1.35 버전으로 업데이트했어요"(✕로 닫음). 창을 열고 있으면 "새 버전(0.1.35)을 받아 두었어요 · 창을 닫으면 알아서 설치하고 다시 켜져요 [지금 업데이트]". 받지 못하면 아래처럼 직접 누르게.
  - 끄면 예전처럼 "새 버전(0.1.35)이 나왔어요 · 지금 업데이트" → 설치 후 재시작.
  - [지금 업데이트]로 다시 켜질 때는 메인 창을 보인다. 설치 프로그램은 처음 켜질 때와 같은 인자로 다시 켜므로, 자동 실행(`--autostart`)으로 켜진 프로그램에서 업데이트하면 트레이로만 켜졌다(사용자 보고). 그래서 설치 직전에 새 버전을 적은 표시(`%APPDATA%\<식별자>\show-after-update`)를 남기고, 켜질 때 표시의 버전이 지금 버전과 같으면 창을 보인다. 표시는 한 번 쓰고 지운다(설치가 안 됐으면 버전이 달라 창을 띄우지 않음). `relaunch.rs`.
  - 업데이트 서명 키: 개인 키는 GitHub Secrets(`TAURI_SIGNING_PRIVATE_KEY`, `..._PASSWORD`)에만, 별도 백업 필수(잃으면 기존 설치본에 업데이트 불가).
  - 개인 키 암호는 `TAURI_SIGNING_PRIVATE_KEY_PASSWORD`. 공개 키는 `tauri.conf.json`의 `plugins.updater.pubkey`.
  - `latest.json` + 설치 파일은 **공개 저장소 `08hwichemi/file-organizer-releases`의 Releases**(코드는 비공개 저장소에 그대로). 이 저장소에 쓰는 토큰은 Secrets `RELEASES_TOKEN`.
- 빌드·배포: **main에 병합될 때마다**(설명서·문서만 바뀐 병합은 빼고 — `docs/**`·`*.md`·manual.yml만 바뀌면 새 버전을 만들지 않아 바뀐 것 없는 업데이트 알림이 뜨지 않는다, 사용자 지적) GitHub Actions(`release.yml`, windows-latest)가 버전 `0.1.<실행 번호>`로 빌드·서명하고, 설치 파일을 영문 이름(`AutoFolder_<버전>_x64-setup.exe`, 0.1.18까지는 `file-organizer_…`)으로 바꿔 `latest.json`과 함께 공개 저장소 Releases에 올린다(`scripts/prepare-release.sh`). 설치된 프로그램은 다음 확인 때 스스로 업데이트한다. Secrets가 없으면 배포를 건너뛴다.
- PR마다 설치 파일을 아티팩트로도 만든다(업데이트 서명 없음). 버전은 그때 배포된 최신 버전 + 1(예: 최신 0.1.20 → 시험판 0.1.21)이고, 왼쪽 위·설정의 버전 옆에 "시험판 · PR n" 이름표가 붙는다. 예전처럼 0.1.0이면 정식판이 깔린 PC에서 더 낮은 버전이라 설치가 꼬이거나 "새 버전이 있어요"로 정식판이 시험판을 덮어써서 PR을 확인할 수 없었다(사용자 보고). 병합되면 정식판이 같은 번호나 그다음 번호로 나오므로 그 뒤로는 정식판을 따라간다.
- "알 수 없는 게시자" 경고(SmartScreen): **코드 서명 없이 무료로 배포**하고 "추가 정보 → 실행"을 안내한다(사용자 결정). 까닭: 개인용 Microsoft 서명 서비스는 미국·캐나다만, 인증서는 연 수십만 원이고 2024년부터는 EV 인증서도 경고를 바로 없애 주지 않는다. 경고는 처음 설치 때만 나오고 자동 업데이트에는 안 나온다.
  - 받기는 **크롬을 권한다**(엣지는 받을 때 "유지 → 자세히 표시 → 그래도 계속"까지 단계가 많음. 링크를 크롬으로 강제로 열 방법은 없어 주소 복사로 안내).
  - 사용 설명서(설치 포함): **https://08hwichemi.github.io/file-organizer-releases/** (공개 저장소의 GitHub Pages, `gh-pages` 가지. main에 병합되면 `.github/workflows/manual.yml`이 `docs/manual/tools/site.mjs`로 묶어 올린다. 예전 Claude 주소 UjLpBr6…는 쓰지 않음) — 한 화면에 한 장면(설치 → 처음 설정 → ★새 파일 정리 → ★자동 분류 → 정리한 뒤 → 그 밖에 → 자주 묻는 것). 원본 `docs/manual/index.html`, 그림 `docs/manual/img`(WebP, 넘기기 전에 미리 받아 둠. 앱 화면은 `docs/manual/tools/shots.mjs`로 가짜 데이터 화면을 찍고, Windows·브라우저 화면은 `windows-screens.html`의 예시 그림).
  - 설명서 시작은 세 장(사용자 요청: 처음 보는 사람이 첫 장에서 무엇인지 확실히 알게, 글씨를 크게): ① 무슨 프로그램인지 — 큰 제목, 한 문장 설명, '정리 전(바탕화면·다운로드에 섞인 파일) → 정리 후(폴더별)' 그림, 설치 5분·되돌리기·지우지 않음 ② 어디에 뜨는지 — Windows 바탕화면 전체 그림에서 오른쪽 아래(작업 표시줄 바로 위)에 창이 뜬 자리를 주황 테두리로(`docs/manual/tools/desktop-scene.html` → desk.webp, 창은 실제 화면 popup.webp) ③ 이렇게 써요 — 창이 뜨면 → [넣기] 한 번 → 쌓인 파일은 [자동 분류] 세 단계. 예전 첫 장(작은 주요 기능 카드 두 개)은 없앴다. 노트북 화면(1280×720)에서도 한 화면에 들어간다. 처음 설정 끝(7장)에는 트레이 장면: 창을 닫아도 트레이에서 지켜봄, 컴퓨터를 켜면 저절로 켜짐, 아이콘 누르면 열기·오른쪽 클릭 메뉴(열기·정리함·파일 검색·일시 정지·끄기), 아이콘이 안 보이면 ^, 자동 실행 끄는 곳(`docs/manual/tools/tray-scene.html` → tray.webp).

  - 예전 설치 안내 페이지(KBogxpj8…)는 설명서로 안내만 한다.

## 8. 기술 구조

- Tauri 2 + React 18 + TypeScript + Vite. 상태 Zustand, 끌어다 놓기 dnd-kit, 폰트 Pretendard(번들 포함), 아이콘 Lucide.
- 화면은 파일을 직접 만지지 않고 Rust 명령(invoke)을 부른다. 새 파일·이동 결과는 Rust → 이벤트.
- Rust 모듈: `watcher`(감시·저장 완료 판단) `mover`(이동·되돌리기·재시도) `rules`(규칙 저장·매칭·저장 위치) `naming`(파일 이름 단어·연도/학기/학급 인식·학년도 계산) `classify`(자동 분류: 폴더 이름·자동 분류 단어·형식) `search`(자체 색인: 읽기·찾기·바뀐 폴더 다시 읽기) `everything`(SDK) `finder`(검색 화면 명령·단축키·색인 감시) `renamer`(이름 한꺼번에 바꾸기: 적은 이름을 블록으로 알아듣기·블록으로 이름 짓기·명렬표·묶음 기록) `db`(SQLite) `tray`(트레이·자동 실행·단축키) + updater.
- 창: 팝업 = 테두리 없는 작은 창(항상 위, 오른쪽 아래), 메인 = 별도 창(파일 검색도 메인 창 안 화면), 창 X = 숨기기. 메인 창은 켤 때 화면에 맞춰 크게(사용자 요청): 작업 영역의 85%, 1100×720 ~ 1600×1000(화면이 작으면 화면 안에), 가운데.
- 데이터: `%APPDATA%\com.hwichemi.file-organizer\data.db`(앱 식별자 폴더) 하나에 설정·규칙·이동 기록·정리함·자체 색인. 폴더 구조는 저장하지 않고 디스크를 직접 읽는다.
- 저장소: `src/`(React), `src-tauri/`(Rust), `docs/`(기획서·시안), `.github/workflows/`.
  - `src/lib/backend.ts`가 Rust 명령을 부르는 유일한 통로. Tauri 밖(브라우저)에서는 `src/mocks/`의 가짜 데이터를 돌려준다.
  - 앱 식별자 `com.hwichemi.file-organizer`, 실행 파일 이름 `file-organizer.exe`(표시 이름 = productName "AutoFolder", 만든 곳 = "이용휘"). 식별자는 사용자 자료 폴더·한 개만 실행·업데이트에 쓰이므로 배포 후에는 바꾸지 않는다.
  - 이름 바꾸기(파일 정리 도우미 → AutoFolder): 설치 프로그램은 이름으로 설치 폴더(`%LOCALAPPDATA%\<이름>`)·"프로그램 추가/제거" 항목·바로 가기·자동 실행을 만든다. 그래서 `src-tauri/windows/hooks.nsh`(설치 뒤 끼워 넣는 부분)가 예전 설치를 넘긴다: 예전에 넣은 파일만 지우고 빈 폴더만 지움(통째로 지우지 않음), 예전 항목·설치 기록·이름 붙은 자동 실행 지움, 시작 메뉴·바탕화면 바로 가기는 이름만 AutoFolder로 바꿔 새 실행 파일을 가리키게(자동 업데이트는 `/UPDATE`로 깔아 바로 가기를 새로 만들지 않으므로), 작업 표시줄 고정은 새 실행 파일을 가리키게. 사용자 자료(식별자 폴더)는 그대로. 자동 실행은 프로그램이 켜질 때 새 이름으로 다시 등록. PR 빌드가 windows-latest에서 0.1.18을 깐 뒤 새 설치 파일을 `/S /UPDATE`로 깔아 이것들을 확인한다(`scripts/check-rename-migration.ps1`).

## 9. 개발 단계 (단계마다 PR 하나)

클라우드(리눅스)에서는 Windows 창·트레이·Everything을 띄울 수 없다.
- 클라우드에서 확인: React 화면(브라우저 + 가짜 데이터), Rust 로직 단위 테스트, 컴파일.
- PC에서 확인: Actions가 만든 설치 파일을 설치해 실제 동작 확인.

1. 뼈대 — Tauri 2 + React + TS + Vite, 폴더 구조, Windows 빌드 워크플로(PR마다 설치 파일 아티팩트). 완료: 받은 설치 파일이 설치되고 빈 창이 뜬다.
2. 정리 폴더와 처음 실행 — SQLite 설정, 정리 폴더 고르기, 예시 구조 생성, 폴더 트리 읽기, 새 파일 알림 방식 선택(설정에서 변경). 완료: 고른 구조가 실제로 만들어진다.
3. 감시 + 팝업 — 감시, 저장 완료 판단, 팝업(3-1), 폴더 창 탐색, 새 폴더, 이동, 되돌리기, 기록. 완료: 크롬으로 PDF를 받으면 3초 안에 팝업, 고른 폴더로 이동, 되돌리기 동작.
4. 정리함 — 메인 창(3-2), 끌어다 놓기, 골라서 넣기, 숫자 키, 자주 쓰는 폴더. 완료: 세 가지 넣는 방법 모두 동작.
5. 규칙 — 규칙 카드, 추천, 연도·학기·학급 인식, 바로 정리 모드, 규칙 목록. 완료: 같은 형식 파일에 추천이 뜬다. 날짜 계산은 단위 테스트.
6. 트레이·자동 실행·한 개만 실행·설정. 완료: 재부팅 후 트레이에만 뜨고, 창 X 후에도 감시 계속.
7. 검색 — 자체 색인 → Everything SDK → 검색창. 완료: Everything 있는/없는 PC 모두 검색. (뒤에 고침: 검색창 → 메인 창 안 화면, Everything 없이도 PC 전체 자체 색인.)
8. 이름 한꺼번에 바꾸기(3-4, 사용자 요청으로 추가) — 폴더·파일 고르기, ~~틀·글자 바꾸기, 규칙 알아내기~~(0.1.15 뒤: 첫 파일을 적으면 블록으로 알아듣기로 바꿈), 명렬표(저장 안 함), 미리보기, 묶음 되돌리기. 완료: 번호로 된 과제 파일 30개를 명렬표로 `이름(번호)`로 바꾸고 한 번에 되돌린다. 이름 짓기·조각 비교·번호 읽기·명렬표 읽기·엇갈린 이름 바꾸기는 단위 테스트.
9. 업데이트와 배포 — ~~서명 키, updater, Releases~~(3단계 뒤로 앞당겨 완료: 병합할 때마다 자동 배포), ~~Everything 포함~~(자체 색인으로 PC 전체를 찾게 되어 뺌), 라이선스 고지(설정 → 정보, 설치 폴더 `resources/THIRD_PARTY.txt`). 완료: 설치본이 다음 병합 뒤 스스로 업데이트(0.1.x 배포에서 이미 확인 중).
