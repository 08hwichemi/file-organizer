# 파일 정리 도우미 기획서

> 원본(편집용): https://claude.ai/code/artifact/3e797a23-ced0-467f-9b4c-7d85e72913ae
> 화면 시안(눌러 볼 수 있음): https://claude.ai/artifact/47zLo1gXgvr5PqTTeFH6g6 — 같은 내용이 `docs/design/*.dc.html`에 있다.
> 이 파일과 원본이 다르면 원본이 우선이다. 바뀐 결정은 이 파일에도 반영한다.

## 1. 개요

바탕화면·다운로드에 새 파일이 저장되면 작은 창을 띄워, 클릭 한두 번으로 원하는 폴더에 넣게 해 주는 Windows 프로그램.
쓰는 사람마다 폴더 구조와 파일 이름 습관이 다르므로, 미리 정한 규칙 대신 **각자 만든 폴더와 쓰면서 쌓이는 규칙**으로 정리한다.

- 쓰는 사람: 만든 사람 본인 + 나눠 받을 선생님들. 컴퓨터에 익숙하지 않은 사람도 설명 없이 쓸 수 있어야 한다.
- 플랫폼: Windows 10·11. 설치형, 트레이 상주, 컴퓨터 켜면 자동 실행.

설계 원칙
1. 규칙이 없어도 바로 쓸 수 있다 — 폴더만 있으면 팝업에서 폴더를 눌러 넣는다.
2. 규칙은 쓰면서 생긴다 — 위치를 고르면 "다음에도 여기에?"라고 묻고, 파일 이름의 단어를 눌러 규칙으로 저장한다.
3. 폴더는 실제 폴더처럼 보인다 — 목록이 아니라 탐색기처럼 폴더 아이콘이 놓여 있고, 누르면 안으로 들어간다.
4. 실수해도 바로 돌린다 — 모든 이동은 되돌리기 가능, 기록이 남는다. 지우기는 휴지통으로만(되돌리기·복원 가능).
5. 깔끔하고 모던한 화면 — 한글은 단어 중간에서 줄바꿈하지 않고(`word-break: keep-all`), 버튼 줄에서 버튼 하나만 다음 줄로 내려가지 않는다.

## 2. 핵심 흐름

```
새 파일 저장(바탕화면·다운로드)
  → 저장 끝났나 확인(약 2초간 변화 없음)
  → [자동 분류 모드] → 이름·형식으로 나눌 수 있으면 이동 + 알림, 모르면 정리함으로(4-1)
  → [모아 두고 나중에 정리] → 팝업 없이 정리함으로
  → [바로 정리 모드 + 규칙에 맞음] → 팝업 없이 이동 + 알림(팝업 창에 "규칙대로 정리했어요" + 되돌리기, 8초 뒤 닫힘)
  → [그 외] → 팝업
        ├ 넣기 → 폴더로 이동·기록 → 규칙 만들기 카드("다음에도 여기에?")
        └ 나중에 정리 → 정리함 → (끌어다 놓기·체크 후 넣기·숫자 키) → 폴더로 이동·기록
```
기본 설정은 "바로 물어보기 + 추천만"이라 대부분의 파일이 팝업을 거친다.
새 파일 알림 방식(처음 실행에서 고르고 설정에서 바꿈)
- **바로 물어보기**(기본): 새 파일마다 팝업.
- **모아 두고 나중에 정리**: 팝업을 띄우지 않고 정리함에 모은다. 사용자가 원할 때 프로그램을 열어 정리한다.

## 3. 화면

### 3-1. 새 파일 팝업 (`docs/design/popup.dc.html`)
화면 오른쪽 아래, 폭 460px, 항상 위.
1. 파일 정보: 형식 배지(HWP·PDF…), 이름, "다운로드에 방금 저장됨 · 크기". 연필 버튼 = 이름 바꾸기.
2. 추천 위치: 규칙에 맞는 폴더 하나 + 규칙 이름("이름의 ‘수행평가’ 규칙"). 누르면 선택.
3. 최근 넣은 곳 3개: 버튼 또는 숫자 키 1·2·3.
4. 폴더 창: 탐색기처럼 폴더 아이콘 격자(한 줄 4개). ‹ 버튼 + 경로(정리 폴더 › 평가 › 수행평가). 한 번 누르면 선택, 두 번 누르거나 › 를 누르면 안으로. 돋보기 = 폴더 이름 검색. 마지막 칸 "+ 새 폴더" = 지금 보는 폴더 안에 생성 후 선택.
5. 아래: "넣을 곳: 경로", [나중에 정리] [다른 위치…] [넣기]. Enter = 넣기, Esc = 나중에 정리.
6. 넣은 뒤: "정리했어요" + 되돌리기, 규칙 만들기 카드("다음에도 비슷한 파일은 여기에 넣을까요?" — 이름 단어 고르기, 넣은 폴더 이름과 같은 단어는 미리 골라 둠). "이번만" = 닫기. 추천대로 넣었으면 카드 대신 "…규칙대로 넣었어요".
- 추천이 있으면 그 폴더를 골라 둔 채, 그 폴더의 상위 폴더가 열린 채 시작(폴더 칸에 "추천" 표시). 추천 폴더가 아직 없으면(새 연도·학기) 넣을 때 만든다.
- 여러 파일이 한꺼번에 오면 하나씩 + "남은 파일 n개 · 모두 추천대로".

### 3-2. 정리함 (`docs/design/inbox.dc.html`)
메인 창. 미룬 파일, 추천 없는 파일, 팝업을 그냥 닫은 파일이 모인다.
- 왼쪽 파일 칸: 탭(전체·다운로드·바탕화면), 체크박스·배지·이름·출처와 시각, 추천 위치 + [넣기], 위에 [자동 분류](시안의 [추천대로 모두]를 대신함: 미리보기 창에서 넣을 폴더별로 보여 주고, 체크를 끌 수 있고, 확인하면 한꺼번에 넣음 — 4-1).
- 오른쪽 폴더 칸: 경로 + 폴더 아이콘 격자(누르면 안으로), 위에 숫자 키가 붙은 "자주 쓰는 폴더".
- 배치: 두 칸은 창 크기와 상관없이 항상 나란히(파일 칸 240~400px). 정리함 화면은 창 높이에 맞춰 고정되어 화면 전체는 내려가지 않고(두 칸이 어긋나지 않게), 목록·폴더는 칸 안에서 따로 내려간다. 칸이 좁으면 탭이 한 줄을 다 쓰고 [자동 분류]는 아래 줄로. 폴더 격자는 창이 넓으면 한 줄에 더 많이. 창이 좁으면(1000px 이하) 왼쪽 메뉴는 아이콘만. 파일이 없는 폴더 탭은 숨긴다.
  - 자주 쓰는 폴더(1~6): 지금은 자동 — 넣은 횟수가 많은 폴더부터, 모자라면 정리 폴더 바로 아래 폴더로 채움. 누르면 그 폴더로 이동, 파일을 끌어 위에 놓아도 됨. 직접 고르는 설정은 6단계(설정)에서.
- 폴더마다 ⋯ 메뉴: 이름 바꾸기 · 다른 폴더로 옮기기 · 휴지통으로 보내기(정리 폴더 안쪽만, 모두 되돌리기 가능). 이름을 바꾸거나 옮기면 그 안으로 옮긴 기록의 경로도 따라 바뀐다.
- 파일을 고르면 [휴지통] 버튼: 고른 파일을 휴지통으로(되돌리면 정리함으로 돌아옴).
- 파일 칸 위 [지금 있는 파일 가져오기]: 지켜볼 폴더에 원래 있던 파일(시작 전부터 있던 파일)을 정리함으로 불러온다. 이미 정리함에 있는 파일은 그대로.
- 넣는 방법: 폴더 아이콘 위로 끌어다 놓기 · 체크 후 폴더 아래 "여기에 넣기"(폴더 안에서는 "이 폴더에 넣기") · 체크 후 숫자 키.
- 끄는 동안 놓일 폴더 = 파란 아이콘 + 점선 테두리 + "놓으면 여기로".
- 넣을 때마다 "n개 파일을 … 에 넣었어요 · 되돌리기".
- 왼쪽 메뉴: 정리함(개수) · 최근 정리한 파일 · 파일 검색 · 이름 바꾸기(3-4) · 정리 규칙 · 설정, 아래 작동 상태.

### 3-3. 시안 없는 화면 (같은 스타일)
- 파일 검색: 메인 창 왼쪽 메뉴 "파일 검색" = 오른쪽 화면에서 찾는다(따로 창을 띄우지 않음 — 0.1.14의 별도 검색창은 사용자 요청으로 없앰). 단축키(기본 Alt+Space, 설정에서 Ctrl+Alt+F · Ctrl+Shift+Space · 쓰지 않기)·트레이 "파일 검색"은 메인 창을 앞으로 + 검색 화면 + 입력 칸에 초점. 입력 즉시 결과(어디서 찾는지 표시: PC 전체(Everything) / PC 전체(파일 n개) / 읽는 중 / 정리 폴더와 지켜볼 폴더), ↑↓ 고르기, Enter = 열기, Ctrl+Enter = 위치 열기(탐색기에서 골라 둠), Esc = 검색어 지우기, 고른 줄에 [위치] [열기]. 연도·학기·학급으로 거르기(지금 결과에 있는 값만). 다른 화면에 갔다 와도 검색어는 남는다.
- 처음 실행: ① 정리 폴더 — 문서에 새로 / 바탕화면에 새로 / 다른 곳에 새로(`고른 위치\정리 폴더`) / 쓰던 폴더 그대로 ② 폴더 구성 — 폴더를 정해서 시작(교사용 예시를 바탕으로 이름 바꾸기·더하기·빼기, 두 단계까지) / 빈 폴더(쓰던 폴더를 고르면 건너뜀) ③ 지켜볼 폴더(다운로드·바탕화면 + 직접 추가, 하나 이상) ④ 새 파일이 생기면 — 바로 물어보기 / 모아 두고 나중에 정리 ⑤ 확인 후 시작. 이미 있는 폴더·파일은 그대로 둔다.
- 설정: 새 파일이 생기면(바로 물어보기 / 모아 두고 나중에 정리), 정리 방식(추천만 / 바로 정리 / 자동 분류, 추천만일 때 "팝업에 응답이 없으면 n초 뒤 추천 위치에 넣기" — 그대로 기다리기·5·10·20·30초, 아무 곳이나 누르면 멈춤), 학년도·학기(1학기·2학기 시작 달), 지켜볼 폴더, 정리 폴더(위치 바꾸기 + 폴더 구성: 정리함과 같은 폴더 격자 + ⋯ 메뉴), 자주 쓰는 폴더(숫자 키 1~6, 칸마다 직접 고르기 / 자동), 자동 실행, 파일 검색(PC 전체에서 찾기 켬/끔, 단축키), 업데이트 확인, 정보(버전 · 개인정보 안내 · 오픈소스 라이선스). 바꾸면 바로 저장.
  - 정리 폴더 위치 바꾸기: 다른 폴더를 고르면 앞으로 거기에 정리한다. 원래 폴더·파일은 옮기지 않고, 직접 고른 자주 쓰는 폴더는 비운다. 예전 폴더로 가는 규칙은 그대로.
- 정리 규칙(왼쪽 메뉴): 아래쪽에 "자동 분류 단어"(4-1) — 고치기·더하기·빼기·기본 단어로(모두 되돌리기 가능). 위쪽은 규칙 목록(위에서부터 먼저 봄) — 순서 바꾸기(↑↓) · 고치기 · 지우기(되돌리기 가능) · 새 규칙. 규칙마다 조건, 저장 위치(자리표시 포함), 넣은 횟수, 저장 위치 폴더가 없어졌으면 경고.
- 트레이: 열기 · 정리함(개수) · 파일 검색 · 일시 정지/다시 시작 · 끄기. 아이콘을 누르면 메인 창. 창 X = 트레이로 숨김(감시 계속). 메인 창 왼쪽 아래 상태 칸에도 [일시 정지]/[다시 시작].

### 3-4. 이름 한꺼번에 바꾸기 (8단계, 사용자 요청)
폴더를 골라 그 안 파일 이름을 한꺼번에 바꾼다. 예: 번호로 된 학생 과제 `05.hwp` → `김민지(5).hwp`, `scan_001.pdf` → `가정통신문(1).pdf`.
왼쪽 메뉴 "이름 바꾸기"(정리함 · 파일 검색 · **이름 바꾸기** · 정리 규칙 · 설정). 한 화면에서 위에서 아래로: ① 폴더와 파일 → ② 바꾸는 방법 → ③ 미리보기 → [n개 이름 바꾸기].

① 폴더와 파일
- [폴더 고르기]: 정리 폴더 밖 폴더도 된다. 단 드라이브 맨 위·Windows·Program Files 같은 시스템 폴더는 막는다.
- "하위 폴더 파일도"(기본 끔). 켜면 미리보기에 폴더 경로도 보인다.
- 파일 목록: 체크(기본 모두), 숨김·임시 파일(`~$`, `.tmp` 등, 5장 기준)은 뺀다. 순서: 이름순(숫자는 크기대로 — 2 < 10) / 고친 날짜순 / 직접(끌어서). 한 번에 최대 3,000개, 하위 폴더는 8단계 깊이까지(숨김·시스템 폴더 제외).

② 바꾸는 방법(아래 셋을 함께 쓸 수 있고, 틀 → 글자 바꾸기 차례로 적용. 확장자는 바꾸지 않는다)
- **틀로 새로 짓기**: 칸 버튼을 눌러 끼워 넣고 사이에 글자를 적는다. 칸: [원래 이름] [번호] [학생 이름] [조각 1…n] [연도] [학기] [학급] [날짜(고친 날)]. 예 `{학생 이름}({번호})`, `{과제}_{학급}_{번호}`.
  - 번호: "순서대로 매기기"(시작 번호, 자릿수 자동/1/01/001 — 자동 = 가장 큰 번호의 자릿수) 또는 "이름에서 읽기"(아래 규칙 알아내기의 번호 조각, 없으면 이름의 숫자 하나 — 학급 표기 `3-2`·연도·학기는 빼고, `5번`·`과제05`도 5, 여럿이면 마지막. 자동 자릿수 = 그대로 5). 학년반번호 다섯 자리(30205)는 끝 두 자리.
  - [학생 이름]은 [번호] 칸과 같은 번호로 명렬표에서 찾는다. [연도]·[학기]·[학급]이 이름에 없으면 빈 칸(겹친 `_`·공백은 정리). 모르는 `{…}`는 글자 그대로.
- **글자 바꾸기**: 찾을 글자 → 바꿀 글자(여러 줄), 앞에 붙이기, 뒤에 붙이기, 지우기(바꿀 글자를 비움). 대소문자 무시. 바꾼 뒤 겹친 공백·`_`는 하나로.
- **규칙 알아내기**(폴더를 고르면 먼저 해 봄): 이름을 조각(`_` `-` 공백 괄호, 숫자 사이 `-`는 학급으로 붙여 둠 — 규칙 카드와 같은 기준)으로 나눠 자리별로 비교한다.
  - 모든 파일에서 같은 조각 = 공통(예: 과제명), 자리마다 바뀌는 숫자 = 번호, `3-2` = 학급, `2027`·`1학기` = 연도·학기.
  - 알아낸 모양을 조각 칩으로 보여 주고(누르면 틀에 그 칸을 끼워 넣음 — 끌어서 순서 바꾸기 대신 틀 글자에서 순서를 정한다), 틀을 1~3개 제안한다(누르면 틀에 들어감). 예: "번호로 된 이름이네요 → `{학생 이름}({번호})`"(명렬표가 있을 때), "`독후감_3-2_05` 모양 → `{번호}_{학생 이름}_{과제}`".
  - 이름 모양이 서로 다르면 가장 많은 모양을 기준으로 하고, 맞지 않는 파일은 미리보기에 표시해 건너뛴다.

명렬표(학생 이름 넣기, 저장하지 않음)
- 나이스·엑셀에서 "번호 이름" 두 칸을 복사해 붙여 넣는다(탭·쉼표·공백 구분, 머리글 줄은 건너뜀). 학년반번호 다섯 자리(30205)는 끝 두 자리를 번호로.
- 파일의 번호로 이름을 찾아 [학생 이름] 칸에 넣는다. 명렬표에 없는 번호는 빨갛게 표시하고 바꾸지 않는다.
- **디스크에 저장하지 않는다**(화면을 떠나거나 프로그램을 끄면 지운다). 학생 이름이 기록에 남는 것은 바꾼 파일 이름뿐.

③ 미리보기와 실행
- 표: 원래 이름 → 새 이름. 그대로(회색), 겹침(새 이름끼리 같거나 폴더에 이미 있음 → 덮어쓰지 않고 `(2)`를 붙인다고 표시), 쓸 수 없음(빈 이름, `\ / : * ? " < > |`, 경로 260자 넘음 → 빨강, 건너뜀).
- [n개 이름 바꾸기]: 서로 이름이 엇갈리는 경우(a→b, b→a)도 임시 이름을 거쳐 안전하게 — 먼저 모두 `~이름바꾸는중-….tmp`(감시·검색이 무시하는 이름)로 바꾼 뒤 새 이름으로, 그사이 자리가 찼으면 번호. 실행할 때 미리보기를 다시 계산한다(그사이 바뀐 것 반영). 열려 있는 파일은 건너뛰고 끝에 알린다. 바뀐 이름은 새 파일 감시가 새 파일로 잡지 않는다.
- 바꾼 것은 모두 이동 기록(원래 경로 → 새 경로, 같은 묶음 번호 — DB 표 버전 6 `moves.batch`)에 남고, 알림 "n개 파일 이름을 바꿨어요 · **되돌리기**"로 묶음 전체를 한 번에 되돌린다(되돌릴 때도 임시 이름을 거침). 그 파일로 옮겼던 예전 이동 기록·정리함 항목은 새 이름을 따라간다(그 이동도 계속 되돌릴 수 있게). 규칙은 폴더 경로만 쓰므로 그대로.

## 4. 규칙

규칙 = "조건 → 저장 위치". 기본 생성 경로는 팝업에서 위치를 고른 뒤 단어를 눌러 저장. 정리 규칙 목록은 고치고 지우는 곳(확장자·출처 규칙은 여기서 "새 규칙"으로 만든다). 새 규칙은 맨 위에 놓인다(예전 규칙에 가려지지 않게).

조건(위에서부터 먼저 맞는 규칙 하나)
| 종류 | 예 | 비고 |
| --- | --- | --- |
| 파일 이름 단어 | ‘수행평가’ 포함, ‘2027’과 ‘수행평가’ 모두 포함, ‘중간고사’·‘기말고사’ 중 하나라도 포함 | 기본. 대소문자 무시. 단어가 여럿이면 규칙마다 "모두 들어 있으면 / 하나라도 있으면"(기본 모두) |
| 확장자 | .hwp, .hwpx | 단어와 함께 쓰면 둘 다 맞아야. 단어 없이 확장자만 있는 규칙은 단어 규칙이 하나도 안 맞을 때 마지막 기준 |
| 출처 | 다운로드에서 온 파일만 | 선택 |

저장 위치와 자동 하위 폴더
- 경로 일부를 **[연도] [학기] [학급]** 자리표시로 바꿀 수 있다. 팝업·규칙 편집의 "연도·학기 폴더는 파일마다 알아서 나누기"를 켜면, 고른 폴더 경로(정리 폴더 아래) 중 이름이 연도·학기·학급으로만 된 폴더가 자리표시가 된다: `2027` → [연도], `2027학년도` → [연도]학년도, `1학기/2학기` → [학기], `2027 1학기` → [연도] [학기], `3-2` → [학급]. `학급 3-2`처럼 다른 글자가 섞인 폴더는 그대로.
- 저장은 고른 폴더 경로 그대로 + "나누기" 여부. 폴더 이름을 바꾸거나 옮기면 규칙의 저장 위치도 따라 바뀐다. 자리표시 앞부분 폴더가 없어지면 그 규칙은 추천하지 않고 규칙 목록에 경고.
- 예: 평가 › 수행평가 › [연도] › [학기] → `2028_2학기_…` 파일은 … › 2028 › 2학기. 없으면 만든다.
- 값을 읽는 순서: 파일 이름 → 없으면 오늘 날짜.
- 학년도·학기: 3~8월 = 그 해 1학기, 9~12월 = 그 해 2학기, 1~2월 = 전년도 2학기. 경계 월은 설정에서 변경 가능.
- 연도: `2027`, `27학년도`. 학기: 1차 버전은 `n학기`만(`1-1` 같은 표기는 학급과 헷갈림).
- 학급: `3-2`, `3학년 2반`, `302` → `3-2`로 통일. 숫자 3자리(`302`)는 그 규칙이 [학급]을 쓸 때만. 학년 없이 `3반`이면 `3반` 폴더. 이름에 학급이 없으면 [학급] 폴더 단계는 건너뛴다(오늘 날짜로 정할 수 없으므로).
- 날짜와 섞인 `-`(`2027-10-13`)는 학급으로 보지 않는다. 연도는 2000~2099의 네 자리 숫자만(`20261013` 같은 여덟 자리는 아님). 오늘 날짜는 이 PC의 시간대 기준.

추천과 자동 이동
- 기본은 추천만. "바로 정리"를 켜면 규칙에 맞는 파일은 팝업 없이 이동 + 알림(되돌리면 팝업에서 다시 물어봄), 규칙 없는 파일은 "새 파일이 생기면" 설정대로(팝업). 옮기지 못하면(파일이 열려 있음 등) 팝업으로 물어본다.
- "모아 두고 나중에 정리"일 때는 바로 정리하지 않고 모두 정리함으로. 정리함에서 파일마다 추천 위치 + [넣기], 위에 [자동 분류].
- 같은 규칙에서 사용자가 추천과 다른 **같은** 폴더를 세 번 연속 고르면 넣은 뒤 "규칙을 바꿀까요?" → [그대로 두기] / [이 폴더로 바꾸기]. 중간에 추천대로 넣거나 다른 폴더를 고르면 처음부터 센다.
- 추천과 다른 곳에 넣었을 때(세 번째가 아니면)는 규칙 만들기 카드를 보여 준다.
- 기록: 추천(규칙)대로 넣은 이동은 그 규칙 번호를 남긴다(규칙 목록의 "n번 정리했어요", 되돌린 것 제외).

## 4-1. 자동 분류

규칙을 만들지 않아도 파일 이름·형식을 보고 알아서 나눈다. 사용자 결정(5단계): 정리함 버튼 + 새 파일 둘 다, 구별이 안 되는 파일은 정리함에 남김, 기준은 폴더 이름 + 교사용 단어 + 파일 형식.

- 순서: ① 정리 규칙 → ② 이름 단어 → ③ 파일 형식 → ④ 모르면 정리함(원래 자리 그대로).
- ② 이름 단어: 정리 폴더 안 폴더 이름(4단계 깊이까지, 두 글자 이상, 숫자만·연도·학기·학급 폴더 제외)과 "자동 분류 단어" 중 파일 이름에 든 **가장 긴 단어**(같으면 폴더 이름). 대소문자 무시.
- 자동 분류 단어(교사용 기본, 정리 규칙 화면에서 고침): 공문(공문·시행문·협조·회신), 회의록(회의록·협의회·회의), 계획서(계획서·계획), 가정통신문(가정통신문·통신문), 수업(수업·학습지·활동지·교안·지도안), 수행평가(수행평가·채점기준·루브릭), 지필고사(지필·중간고사·기말고사·문항정보표·이원목적·시험지·감독), 상담, 출결(출결·결석·지각·조퇴), 생활기록부(생활기록부·생기부·세특·세부능력·행동특성·창체·진로활동·동아리), 연수(연수·이수증). 폴더 자리는 교사용 예시 구조(예: 업무 › 공문).
  - 같은 이름의 폴더가 정리 폴더 어딘가에 있으면(얕은 것부터) 거기로, 없으면 정해 둔 자리에 **만든다**.
- ③ 파일 형식: `정리 폴더\형식별\` 아래 한글 문서·워드 문서·PDF·엑셀·발표 자료·사진·동영상·소리·압축 파일·텍스트(없으면 만든다). 형식별 폴더 안의 폴더 이름은 ②의 기준이 아니다.
- ④ 설치 파일(.exe·.msi) 등 형식도 모르는 파일은 옮기지 않는다.
- 언제: 정리함 [자동 분류](미리보기 → 확인), 그리고 설정 "정리 방식 → 자동 분류"면 새 파일마다(묻지 않고 옮긴 뒤 팝업 창에 알림 + 되돌리기, 나누지 못한 파일은 "새 파일이 생기면" 설정과 상관없이 정리함으로).
- 팝업·정리함 줄의 "추천 위치"도 ①②로 정한다(③ 형식은 추천하지 않음). 추천대로 넣으면 규칙 만들기 카드는 띄우지 않는다.
- 파일 이름은 PC 안에서만 본다(AI 등 밖으로 보내지 않음).

## 5. 파일 감지 세부

- 감시 대상: 지켜볼 폴더의 바로 아래 파일만(하위 폴더 X). 바탕화면·다운로드 실제 위치는 Known Folder API(OneDrive 이동 포함).
- 방식: 파일 시스템 알림(`notify` 크레이트) + 1.5초 주기 확인 보조(저장 중인 파일이 있으면 0.5초).
- 저장 완료: 크기·수정 시각이 약 2초 그대로(3초 안에 팝업이 뜨도록) + 크기 > 0 + 같은 이름의 `.crdownload` `.part` `.download`가 없음.
- 건너뜀: `.crdownload .part .tmp .download .lnk .url .ini`, `~` `~$` `.`으로 시작, 확장자 없음(엑셀 임시), 숨김·시스템, 폴더.
- 시작 시 이미 있던 파일: 팝업 X. 정리함 "지금 있는 파일 가져오기"로.
- 열린 파일(잠김): "파일이 열려 있어요. 닫으면 옮길게요" 후 재시도(최대 3시간).
- 같은 이름: 덮어쓰지 않고 `이름 (2).hwp`.
- 다른 드라이브: 복사 → 원본 삭제, 삭제 실패 시 복사본 삭제 후 오류.
- 기록: (원래 위치, 옮긴 위치, 시각, 규칙). 되돌리기 시 감시가 다시 새 파일로 잡지 않게 표시.
- 일시 정지: 정지 중 들어온 파일은 팝업·자동 정리 없이 정리함으로. 프로그램을 다시 켜면 풀린다.
- **사용자 파일·폴더를 영구 삭제하는 코드는 만들지 않는다.** 지우기는 휴지통으로 보내기만(`trash` 크레이트), 보낸 기록(`deletions` 표)으로 되돌린다. 휴지통이 없는 드라이브(USB·네트워크)는 Windows가 바로 지울 수 있어 지우기를 막는다(고정 디스크만).

## 6. 검색

- 사용자 결정(7단계 뒤): Everything을 깔지 않아도 PC 전체에서 찾는다. Everything의 빠른 검색 엔진(NTFS 목록을 직접 읽음, 관리자 권한 필요)은 따로 설치하는 비공개 프로그램이고, SDK는 켜져 있는 Everything과 이야기하는 통로일 뿐이라 프로그램 안에 넣을 수 없다. 그래서 같은 일을 하는 **자체 색인**을 만든다.
- 순서: ① Everything이 켜져 있으면 Everything(공식 SDK, IPC, `Everything64.dll`, 역분석하지 않음) ② 아니면 자체 색인. 이미 Everything을 쓰는 PC는 그대로 빠르고, 없는 PC도 PC 전체를 찾는다. Everything 설치 파일은 함께 넣지 않는다(9단계에서 뺌).
- 자체 색인 범위(설정 "PC 전체에서 찾기", 기본 켬): 고정 디스크(C:\ D:\ …) 전체에서 빼는 곳 — 드라이브 바로 아래 Windows·Program Files·ProgramData·Recovery 등, 어디서든 AppData·node_modules·`$Recycle.Bin`·`.`/`$`/`~`로 시작하는 폴더, 숨김·시스템 속성, 바로 가기 폴더(심볼릭 링크·연결 지점). 파일은 `~$`·`.tmp`·`.crdownload`·`.lnk` 등을 뺀다. 끄면 정리 폴더(하위 폴더까지) + 지켜볼 폴더(바로 아래)만. 정리 폴더·지켜볼 폴더가 빼는 곳 안에 있어도 그것은 읽는다.
- 읽기: 켤 때 뒤에서(낮은 우선순위 스레드, 디스크도 양보). PC 전체를 처음 읽는 동안에는 정리 폴더·지켜볼 폴더부터 먼저 읽어 그 안에서 찾고, 화면에 "PC 전체를 읽는 중(파일 n개)"을 보여 준다. 다 읽으면 지금 검색어로 다시 찾는다.
- 최신으로 맞추기: 읽은 곳을 파일 시스템 알림(`notify`, 하위 폴더까지)으로 지켜보다가 바뀐 폴더만 2초마다 모아 다시 읽는다. 알림이 넘치거나(놓쳤을 수 있음) 2만 곳 넘게 한꺼번에 바뀌면 처음부터 다시 읽는다(10분에 한 번까지). PC 전체는 6시간마다, 정리 폴더 범위는 검색 화면을 열 때 2분이 지났으면 다시 읽는다. Everything이 켜져 있으면 메모리를 아끼려고 정리 폴더 범위만 읽어 둔다.
- 저장 방식: SQLite FTS5 대신 메모리 목록 + 글자 포함 검색(한글은 단어 중간도 찾아야 해서 — ‘평가’로 ‘수행평가’). 폴더는 한 번만, 파일은 폴더 번호 + 이름(한 덩어리 문자열에 이어 붙임)만 들고 있다. 최대 150만 개(약 100MB). 디스크에 저장하지 않는다(켤 때마다 새로 읽음).
- 찾는 법: 띄어 쓴 낱말이 모두 경로(폴더 이름 포함)에 있는 파일. 대소문자 무시(영문). 이름에 모두 있는 파일이 먼저, 그다음 최근에 고친 순. 최대 200개. Everything도 같은 식(파일만, 휴지통·임시 폴더 제외).
- 결과에 연도·학기·학급(파일 이름 → 없으면 가까운 폴더 이름)과, 규칙으로 넣은 파일이면 그 규칙을 붙여 거르기에 사용.
- `Everything64.dll`은 저장소에 넣지 않고, 설치 파일을 만들 때 `scripts/fetch-everything-sdk.ps1`이 voidtools 공식 배포본(Everything-SDK.zip)에서 받아 `src-tauri/resources/`에 넣는다(못 받으면 경고만 하고 자체 색인으로). 라이선스 고지는 `resources/THIRD_PARTY.txt` 하나(설치 폴더에 함께 들어가고, 설정 → 정보 → [오픈소스 라이선스]에서도 같은 글을 보여 줌): Everything SDK(MIT), Pretendard(SIL OFL 1.1 전문), Tauri·React·Zustand·dnd kit·rusqlite·trash·chrono·serde·windows-sys(MIT), Lucide·libloading(ISC), SQLite(공개 도메인), notify(CC0).

## 7. 설치·자동 실행·업데이트·배포

- 설치: Tauri NSIS, `installMode: currentUser`(관리자 권한 불필요, 이후 업데이트도).
- 자동 실행: autostart 플러그인(기본 켬, 처음 설정을 마칠 때 등록하고 켤 때마다 설정과 맞춤 — 예전 버전에서 업데이트해도 켜짐), `--autostart` 인자로 켜지면 창 없이 트레이로만. 개발용(디버그) 실행 파일은 등록하지 않는다. single-instance 플러그인: 이미 켜져 있으면 그 창을 앞으로.
- 업데이트: updater 플러그인. 시작 시 + 하루 한 번 확인 → "새 버전이 있어요 · 지금 업데이트" → 설치 후 재시작.
  - 업데이트 서명 키: 개인 키는 GitHub Secrets(`TAURI_SIGNING_PRIVATE_KEY`, `..._PASSWORD`)에만, 별도 백업 필수(잃으면 기존 설치본에 업데이트 불가).
  - 개인 키 암호는 `TAURI_SIGNING_PRIVATE_KEY_PASSWORD`. 공개 키는 `tauri.conf.json`의 `plugins.updater.pubkey`.
  - `latest.json` + 설치 파일은 **공개 저장소 `08hwichemi/file-organizer-releases`의 Releases**(코드는 비공개 저장소에 그대로). 이 저장소에 쓰는 토큰은 Secrets `RELEASES_TOKEN`.
- 빌드·배포: **main에 병합될 때마다** GitHub Actions(`release.yml`, windows-latest)가 버전 `0.1.<실행 번호>`로 빌드·서명하고, 설치 파일을 영문 이름(`file-organizer_<버전>_x64-setup.exe`)으로 바꿔 `latest.json`과 함께 공개 저장소 Releases에 올린다(`scripts/prepare-release.sh`). 설치된 프로그램은 다음 확인 때 스스로 업데이트한다. Secrets가 없으면 배포를 건너뛴다.
- PR마다 설치 파일을 아티팩트로도 만든다(버전 0.1.0, 업데이트 서명 없음).
- "알 수 없는 게시자" 경고: 1차는 "추가 정보 → 실행" 안내, 이후 코드 서명 인증서 검토.

## 8. 기술 구조

- Tauri 2 + React 18 + TypeScript + Vite. 상태 Zustand, 끌어다 놓기 dnd-kit, 폰트 Pretendard(번들 포함), 아이콘 Lucide.
- 화면은 파일을 직접 만지지 않고 Rust 명령(invoke)을 부른다. 새 파일·이동 결과는 Rust → 이벤트.
- Rust 모듈: `watcher`(감시·저장 완료 판단) `mover`(이동·되돌리기·재시도) `rules`(규칙 저장·매칭·저장 위치) `naming`(파일 이름 단어·연도/학기/학급 인식·학년도 계산) `classify`(자동 분류: 폴더 이름·자동 분류 단어·형식) `search`(자체 색인: 읽기·찾기·바뀐 폴더 다시 읽기) `everything`(SDK) `finder`(검색 화면 명령·단축키·색인 감시) `renamer`(이름 한꺼번에 바꾸기: 이름 짓기·조각 비교·명렬표·묶음 기록) `db`(SQLite) `tray`(트레이·자동 실행·단축키) + updater.
- 창: 팝업 = 테두리 없는 작은 창(항상 위, 오른쪽 아래), 메인 = 별도 창(파일 검색도 메인 창 안 화면), 창 X = 숨기기.
- 데이터: `%APPDATA%\com.hwichemi.file-organizer\data.db`(앱 식별자 폴더) 하나에 설정·규칙·이동 기록·정리함·자체 색인. 폴더 구조는 저장하지 않고 디스크를 직접 읽는다.
- 저장소: `src/`(React), `src-tauri/`(Rust), `docs/`(기획서·시안), `.github/workflows/`.
  - `src/lib/backend.ts`가 Rust 명령을 부르는 유일한 통로. Tauri 밖(브라우저)에서는 `src/mocks/`의 가짜 데이터를 돌려준다.
  - 앱 식별자 `com.hwichemi.file-organizer`, 실행 파일 이름 `file-organizer.exe`(표시 이름은 "파일 정리 도우미"). 식별자는 설치·업데이트 경로에 쓰이므로 배포 후에는 바꾸지 않는다.

## 9. 개발 단계 (단계마다 PR 하나)

클라우드(리눅스)에서는 Windows 창·트레이·Everything을 띄울 수 없다.
- 클라우드에서 확인: React 화면(브라우저 + 가짜 데이터), Rust 로직 단위 테스트, 컴파일.
- PC에서 확인: Actions가 만든 설치 파일을 설치해 실제 동작 확인.

1. 뼈대 — Tauri 2 + React + TS + Vite, 폴더 구조, Windows 빌드 워크플로(PR마다 설치 파일 아티팩트). 완료: 받은 설치 파일이 설치되고 빈 창이 뜬다.
2. 정리 폴더와 처음 실행 — SQLite 설정, 정리 폴더 고르기, 예시 구조 생성, 폴더 트리 읽기, 새 파일 알림 방식 선택(설정에서 변경). 완료: 고른 구조가 실제로 만들어진다.
3. 감시 + 팝업 — 감시, 저장 완료 판단, 팝업(3-1), 폴더 창 탐색, 새 폴더, 이동, 되돌리기, 기록. 완료: 크롬으로 PDF를 받으면 3초 안에 팝업, 고른 폴더로 이동, 되돌리기 동작.
4. 정리함 — 메인 창(3-2), 끌어다 놓기, 체크 후 넣기, 숫자 키, 자주 쓰는 폴더. 완료: 세 가지 넣는 방법 모두 동작.
5. 규칙 — 규칙 카드, 추천, 연도·학기·학급 인식, 바로 정리 모드, 규칙 목록. 완료: 같은 형식 파일에 추천이 뜬다. 날짜 계산은 단위 테스트.
6. 트레이·자동 실행·한 개만 실행·설정. 완료: 재부팅 후 트레이에만 뜨고, 창 X 후에도 감시 계속.
7. 검색 — 자체 색인 → Everything SDK → 검색창. 완료: Everything 있는/없는 PC 모두 검색. (뒤에 고침: 검색창 → 메인 창 안 화면, Everything 없이도 PC 전체 자체 색인.)
8. 이름 한꺼번에 바꾸기(3-4, 사용자 요청으로 추가) — 폴더·파일 고르기, 틀·글자 바꾸기, 규칙 알아내기, 명렬표(저장 안 함), 미리보기, 묶음 되돌리기. 완료: 번호로 된 과제 파일 30개를 명렬표로 `이름(번호)`로 바꾸고 한 번에 되돌린다. 이름 짓기·조각 비교·번호 읽기·명렬표 읽기·엇갈린 이름 바꾸기는 단위 테스트.
9. 업데이트와 배포 — ~~서명 키, updater, Releases~~(3단계 뒤로 앞당겨 완료: 병합할 때마다 자동 배포), ~~Everything 포함~~(자체 색인으로 PC 전체를 찾게 되어 뺌), 라이선스 고지(설정 → 정보, 설치 폴더 `resources/THIRD_PARTY.txt`). 완료: 설치본이 다음 병합 뒤 스스로 업데이트(0.1.x 배포에서 이미 확인 중).
